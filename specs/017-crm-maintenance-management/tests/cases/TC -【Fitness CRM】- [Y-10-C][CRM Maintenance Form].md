**Data limitations**:

- The mockup's `SAMPLE_STATUS_IN_PROGRESS` constant hardcodes "メンテナンス中" to simulate the start-date lock in the prototype. The **real form must derive the lock condition from the record's actual live computed status** (start/end vs. now), not a hardcoded flag — verify this is truly dynamic in the running app, don't assume the mockup's simulation approach carries over.
- Overlap-boundary cases (TC-C-020/021) need an existing record whose start or end aligns exactly adjacent to the new entry — use the real seed's actual periods (cross-reference with Unit A's execution), not necessarily the table above.
- Format-validation cases (TC-C-012/013) may be difficult to trigger through a native `datetime-local` input, which constrains format at the browser/OS level — if unreachable via normal typing/picker interaction, mark `Block`/N-A and note it, rather than forcing an artificial invalid value the UI itself prevents.
