# TC -【Fitness CRM】- [A-02][移籍管理（一覧）]

**Screen**: Transfer Management List (移籍管理一覧) — `/members/transfers`
**Unit**: Unit 1 of [test-plan.md](../test-plan.md)
**Scope**: The transfer list — page header + count, 詳細フィルター panel (6 filters), filter-result banner, 一括承認 bar, table (selection checkbox, 自動移籍可否, status, row ⋯ menu), pagination, empty/error states, and the three dialogs that live only inside this screen (row 承認, row 否認, 一括承認).
**Out of scope** (per test plan §1): the transfer detail screen (Unit 2 — only "the right detail opens" is checked here), A-01-01 member detail (only "the link opens it"), A-01 member form (data setup only), the header store selector and the demo user switcher (preconditions), notifications (copy only).

## Test-data reference

The backend is **shared and never reset**. Counts are "verify at execution"; every mutating case uses a request the run creates.

**Run prefix**: `QA-TC-A02-<yyyymmdd>-<n>` on member names and in every comment typed. **Off-limits**: every pre-existing request (incl. pending `e94b99aa…` and existing 完了 / 否認 rows) — read-only.
