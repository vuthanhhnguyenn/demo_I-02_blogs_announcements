# TC -【Fitness CRM】- [Y-05-B][App Version Detail]

**Test plan**: [`../test-plan.md`](../test-plan.md) — Unit U2
**Scope**: the app version detail screen `/app-versions/[id]` only — the 「バージョン情報」 card, the header 「削除」 / 「編集」 (予約 only), the delete dialog opened from the header, the not-found and error states, and role access. Out of scope (test plan §1): the list, its row menu and the store URL dialog (`[Y-05-A]`); the create / edit form, its states and the minimum-change confirmation (`[Y-05-C]`); the launch check (Y-05 FR-M007); Y-06.

**Setup owned by this unit** (備考 marker `QA-APV <YYYYMMDD> <purpose>`):

- **X1, X2, X3** — FIT365, 適用開始日時 + 100 / 101 / 102 days at 10:00, every pair blank, 備考 `QA-APV <YYYYMMDD> X1 delete` (X2, X3 alike). Create through the form (`[Y-05-C]`) or a `POST` script.
- **R2** — FIT365, 適用開始日時 T = now + 3 min (a whole minute), every pair blank, 備考 `QA-APV <YYYYMMDD> R2`. Create right before TC-B-047. At T it becomes FIT365's active setting and can never be deleted (local BE only).

**Data limitations**:

- Build order: F1–F3 and S1–S3 come from `[Y-05-C]`'s create cases, P\* and L\* from `[Y-05-A]`, and the E\* for TC-B-032 from `[Y-05-C]`'s edit cases. Run this doc after those.
- TC-B-047–051 are one sitting around R2's start time T. R2 is one-shot: a missed window needs a new R setting, which also stays forever.
- X3: TC-B-042 (401) runs before TC-B-043 (double-click deletes X3). X2: TC-B-070 and the fallback of TC-B-046 run before TC-B-045 deletes it.
- Long 作成者 / 更新者 names, the 5xx / 403 reads and the long toast are pure UI and use route interception (fake data): the seed staff names are short and those errors cannot be provoked for real.
- If the server refused L1's values when `[Y-05-A]` built it, TC-B-061 uses the largest accepted value — record it.
- No count in this doc depends on pre-existing data; the only counts (title count / footer in TC-B-039) are relative (one lower).
