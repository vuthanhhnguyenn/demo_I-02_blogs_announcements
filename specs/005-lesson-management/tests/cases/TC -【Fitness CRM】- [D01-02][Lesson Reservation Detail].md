### Flagged spec/mockup gaps (written to the spec's required behavior; NG if the current build matches the mockup as read)

1. **Missing active-state header badge.** FR-007-01/FR-007-16 require the PageHeader badge to show remaining seats (`N/M 予約済（残りX席）`) in the active state and `中止済み` only when cancelled. The mockup's `badge` prop is `undefined` whenever `!isCancelled` — no remaining-seats badge renders at all in the normal (non-cancelled) state. See TC-006/007.
2. **Header subtitle date/time format differs from the spec's own example.** FR-007-01's example renders the date as `3月5日（水）` and the time range with a wave dash (`9:00〜10:00`); the mockup renders `3/5(水)` and a hyphen (`9:00-10:00`) — inconsistent with the spec text (though consistent with `M/D(day)` shorthand used elsewhere in this app's other screens). Noted for PO/format confirmation, not asserted as a hard NG. See TC-004.
3. **No role gating anywhere on this screen.** The D-01.md permission matrix requires Observer to be blocked (×) from 予約手動入力(FR-006)/予約キャンセル(FR-008)/出席確認(FR-009)/セッションメモ(FR-011)/schedule edit (講師・時間・スタジオ変更), and Trainer to be scoped to only their own sessions for the same actions. The mockup renders every action button/dialog trigger unconditionally for any viewer — no `RoleGatedButton` (or equivalent) wraps any control on this screen, unlike `lesson-schedule.tsx`. Written to the matrix's required behavior in the Permissions section (TC-141–154); expect these to fail against the current build until role gating is added.
4. **Reservation-stats panel is not derived from the reservation list.** The 5 `StatBar` counts (5+2+3+1+3 = 14) and the sidebar's `予約数14` do not match the actual `RESERVATIONS_INITIAL` list, which has 12 rows whose real per-status tally is confirmed=6/tentative=2/attended=2/no-show=1/cancelled=1 = 12. This is exactly the "count/total badge vs. actually-rendered/filtered row count" pattern in `common-gui-validate-checklist.md` (Table section) — flagged as a finding, not assumed intentional. See TC-055/056. Also, the 5 percentages as displayed sum to 99% (36+14+21+7+21), not 100% — see TC-057.
5. **Every mutating confirm button in this screen's dialogs has no wiring** (found by reading the mockup for the exact `onClick`/absence of one on each dialog's primary action — this is inspecting rendered/clickable behavior, not implementation internals): `ReservationCancelModal`'s "キャンセルを確定", `ChangeInstructorModal`'s "講師を変更する", `ChangeTimeModal`'s "時間を変更する", `ChangeStudioModal`'s "スタジオを変更する", `AddReservationModal`'s "追加確定（N名）" (calls `handleClose` only — discards the added list, no reservation is created), the session-memo "メモを保存", and the existing-memo delete (`Trash2`) button. The 3-step lesson-cancel wizard's final "この内容でレッスンを中止する" is the one exception that IS wired (toast + `isCancelled` flip). Each is written as a case asserting the spec's required outcome (list/state actually updates) — expect NG on the others per the current build. See the relevant dialog sections and TC-039, TC-078, TC-086, TC-094, TC-114, TC-133, TC-135.
6. **Add Reservation modal's space-number dropdown offers equipment/pillar slots as assignable seats.** The options are built by filtering `SPACE_DATA` for `status !== "reserved"`, which excludes reserved seats but does **not** exclude `equipment` or `pillar` cells — so `スペース 11`（器材）and `スペース 16`（柱）appear as selectable options alongside the genuinely available seats (3, 10, 15), contradicting the space grid's own legend. Verifiable purely by opening the dropdown (black-box), not by reading implementation. See TC-118.
7. **Cancelled-status card shows fixed values regardless of what was actually chosen in the cancel wizard.** After completing the wizard with any reason/detail, the resulting "中止済み" status card always shows the same hardcoded `2026/04/20 15:30` / `タムタ タム` / `講師欠席（体調不良）` — never the operator's actual wizard input. See TC-097.
8. **Add-Reservation member search shows no empty-state message.** When the typed query matches zero `SEARCH_MEMBERS`, the results table silently renders zero rows — `common-function-checklist.md`'s Search section expects a `"No data"`-equivalent message. See TC-110.

### Data limitations (present anyway, annotated at execution)

- **Pagination boundary.** The seed reservation list has exactly 12 rows; there is no seeded case of exactly 7 or 8 rows (the boundary the test-plan calls out). Boundary cases are written against page-size=7 using the 12-row seed (which does cross the boundary) and separately annotated as "no exact 7/8 seed — inject test data at execution to hit the literal boundary."
- **Header subtitle / grid / stats do not react to the "デモ切替（セッション種別）" toggle** — switching to PTセッション swaps the left-column card and hides the grid/stats, but the PageHeader subtitle text and sidebar "レッスン情報" card stay on their static studio-lesson values (e.g. still show "Zumbaスタジオ"). Treated as a mock/demo-data constraint, not asserted as an NG.
- **Only 5 `SEARCH_MEMBERS` seeded** — the modal's `slice(0, 5)` display cap can never be exercised by a >5-match search with current data; noted, not testable as written.
- **All limited-profile popovers show the same static age/gender ("32歳・女性") and lesson-history rows** regardless of which member row was clicked — a mock-data flatness limitation, not a per-case defect.
