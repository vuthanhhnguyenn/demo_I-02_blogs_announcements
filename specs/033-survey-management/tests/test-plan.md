## 1. Scope

**In scope** — the seven `/surveys/**` screens and the dialogs that live only inside them:

- `/surveys` list: search, 詳細フィルター, `FilterResultBanner`, server-side sort / paging, row actions 編集 / 無効化
- `/surveys/create`, `/surveys/[id]/edit`: basic info, trigger master, question / choice cards, delete-question dialogs, status switch, discard-confirm, save (`POST` / `PUT` + `PATCH …/status`)
- `/surveys/[id]` detail: header actions, header-store scoping, disable dialog (with reason)
- `/surveys/[id]/visibility`: per-store question / choice toggles
- `/surveys/responses` and `/surveys/responses/[responseId]`: cross-survey response list, CSV, response detail
- `/surveys/analytics`: per-questionnaire aggregate, KPIs, CSV
- Role × scope gating of all of the above, including server-enforced refusals (`E-AUTH-100` / `E-AUTH-101`)

| Member app answering a survey (APP side, `E-QST-016/018/020/021/022`)                                                                    | Member app, not CRM                                                                             |
| Enrollment / leave / withdrawal / transfer flows that _fire_ a lifecycle survey                                                          | `025-enrollment-application-mgmt`, `024-leave-withdrawal-management`, `024-transfer-management` |

| Phase 2: オペレーション creation, 手動配信 / 条件トリガー, 評価 / NPS formats, 配信設定 card, 配信数 (FR-005, FR-006, FR-S001/S003/S004) | Not rendered (Known gap 4); only checked for _absence_                                          |

## 5. Coverage focus per unit

These are **added to** gen-testcases' full coverage walk, not a replacement.

**Common to every unit**

- **Real-API behaviour**: server message shown verbatim via `resolveApiErrorMessage` for every `E-QST-nnn` the screen can receive; `401` mid-session (token expired / revoked) → redirect to login, no half-saved state; direct navigation to an unknown / malformed id → `E-QST-001` (404) handled, not a blank page; data persists after reload and after re-login.
- **Role × scope**: assert both the UI gate (button disabled + tooltip copy) **and** the server refusal when the gate is bypassed (direct URL, or calling with a role that should be refused). Codes: a write (`POST`, `PUT …/{id}`, `PATCH …/status`) by a non-HQ role → 403 `E-AUTH-103` (report N2), and a visibility `PUT` by Trainer / Observer → 403 `E-AUTH-103` too; a read / CSV the role may not use → `E-AUTH-100`; a Staff reaching outside its own store → `E-AUTH-101`.
- **UI breakage at 1024×768** — stress every place a value renders (table cell, page title, breadcrumb, card header, dialog title / body, toast, tooltip, badge): max-length full-width Japanese survey name, an equally long unbroken ASCII token, longest trigger name, a row with all 5 brand badges, 30+ questions, a question with 20+ choices, long question / choice text, long member name / store name, 500-char disable reason, long free-text answer. The client sets no max length on survey name / question / choice text — record the server's limit (`E-VAL-*` or accepted) as the observed boundary.

**U1 — Survey list**

- Server-side sort on all 8 sortable columns with URL key → API `sort` mapping (FR-L04); 発動トリガー and ブランド not sortable. Sort + filter + page survive reload / back.
- Real totals: pagination footer vs. actual count; page sizes 25 / 50 / 100 (default 50); page beyond last after a filter narrows.
- Filter count badge excludes search text; active-select highlight; banner inside the Card, summary format; clear keeps page size and sort (FR-L02, FR-L03).
- Cell fallbacks: `triggerName` → `triggerCode` → `—`; empty brands `—`; 回答率 `null` → `—` and 1 decimal; 最終回答日 `YYYY/MM/DD` / `—`; `counseling` row label (Δ11).
- Row gating: ライフサイクル row 編集 / 無効化 → HQ / System only, badge 本部; 無効化 disabled on an already-無効 row; 新規登録 gate + tooltip アンケート作成の権限がありません.
- 無効化 from row → shared dialog → `PATCH …/status`, toast, list refetch; failure toast (e.g. 401 / server error).
- Empty states `filtered` (with 条件をクリア) vs `empty`; row click → detail by `questionnaireId`.

**U2 — Survey form**

- Create body: `name`, `category`, `triggerCode`, `brandEnums: [brand]`, `status`, `questions[]` (array position is the order, no `displayOrder`); `code` generated by the server and shown afterwards in list / detail.
- Validation, client then server: name, ブランドを選択してください, 発動トリガーを選択してください, question text / format, choice text, ≥ 1 question; `未入力の項目があります` + scroll to the first invalid block (including the ≥ 1 question and choice-list blocks). Server-side: `E-QST-006` (choice format without choices), `E-QST-007` (free text with choices), `E-QST-008` / `E-QST-015` (trigger vs category), `E-QST-012` (brand) — reach them by whatever path the UI allows; mark unreachable ones as such.
- **`E-QST-010`**: saving as 有効 (create), activating (無効 → 有効), or editing an already-active survey so that its trigger or brand scope changes, when the resulting brand scope **intersects** another active survey on the same trigger (empty brand = all brands, so it collides with everything on that trigger; two non-empty scopes collide only when they share a brand) → server message shown, nothing saved. A name / description-only edit of an active survey, and any edit of an inactive survey (checked at activation), is not checked. A JOYFIT survey and a FIT365 survey may be active on the same trigger together.
- Trigger options per 種別 from the master, no default, raw code shown when a stored code is missing from the master.
- Edit: stored category added as option; stored brand outside JOYFIT / FIT365 appended; multi-brand joined with `/` and kept until changed.
- Edit save = whole end state via `PUT`: existing ids kept, new ones without id, removed choice retired; reorder persists (Δ7); `PATCH …/status` only when the switch changed; toast アンケートの変更を保存しました; returns to the **list**.
- Delete question: no responses → `この設問を削除しますか？`; has responses → `この設問を削除できません` + 非表示にする → save succeeds, the question is retired and its answers stay readable (was `E-QST-014`, `B4` closed).
- Discard confirm from back link and キャンセル when dirty; no confirm when clean.
- Two tabs editing the same survey: the second `PUT` carries a stale `version` → 409 `E-QST-016`, nothing saved, the form reloads; a retry with the new `version` succeeds (TC-091, TC-092, TC-131).
- 401 during save: no partial write; partial failure of the second call (`B11`).
- Phase 2 absence: no オペレーション option on create, no 評価 / NPS format, no 配信設定 card.

**U3 — Survey detail**

- Header action gating per role (FR-D01): 回答データ (HQ/System/Manager/Staff — FR-D01 no longer lists Trainer, decision 2026-10-23: a Trainer cannot open `/surveys/[id]` (`/403`) and reads answers through `/surveys/responses`, reached from the sidebar アンケート管理 (decision 2026-11-03); `Δ18`), 集計分析 and 店舗別表示設定 (HQ/System/Manager/Staff, tooltip copy), 編集 (ライフサイクル → HQ/System); no 削除 (Δ1).
- Header-store scoping (FR-D02): all-stores → full template, no scope text; a store → hidden questions / choices removed, scope sentence with counts or すべての設問・回答選択肢を使用, empty row この店舗で使う設問はありません. Changes immediately when the header store changes.
- Disable dialog (FR-D03): reason optional, trimmed, empty omitted, 500 / 501 boundary (Δ8), whitespace-only → omitted, cleared on every open; success → badge 無効 after reload; HQ-only on the server (`PATCH …/status` is system / headquarter only).
- 集計分析 carries `survey_id`; 回答データ carries the survey id (back link アンケート詳細に戻る on the target).
- 発動トリガー shows `triggerName` → `triggerCode`.

**U4 — Store visibility**

- Trainer / Observer cannot reach this screen: direct URL → `/403` (`Δ18`). `ヘッダーで対象店舗を選択` in all-stores view.
- One `PUT` per toggle, body only for the current store (`showStoreIds` / `hideStoreIds: [storeId]`); toast names the item; switches disabled while in flight; the detail (U3) reflects it for that store and **not** for another store.
- Question off collapses its choices; last ON choice locked with tooltip.
- Staff: own store only — a Staff hitting another store → `E-AUTH-101` (server-enforced, G-04 所属店舗分). Manager: all stores.
- Rapid toggling / double click; failure shown as the global toast (server `userMessage`) and refetch to the server truth; 401 mid-toggle.
- Visibility persists after reload and re-login; questions listed by `displayOrder`, Q-numbers by position.

**U5 — Responses**

- Filters (FR-R01): date range, ブランド (5), 店舗, 会員区分, テンプレート種別, search; count rule (search excluded, date range counted once); clear keeps `survey_id`.
- Server scope: Staff pinned to own store (another `storeId` → `E-AUTH-101`); Trainer sees only responses of members with a booking on their schedule, `counseling` only (a detail outside that scope → 404 `E-QST-001`; `Δ18`, `B8`); Observer → `/403` on every `/surveys/**` (`E-AUTH-100`, expected, `Δ18`).
- 状態 column four values derived from `responseStatus` / `isComplete`; brand spelling normalised; 回答日時 date + time; subtitle `対象: <アンケート名>`; back link depends on the presence of a survey id.
- CSV (FR-R03): file content follows the current filters, opens in Excel without mojibake (client BOM), toast; filename (`B2`); CSV denied for Trainer (server; Observer never reaches the screen, `Δ18`) and for a position without `can_export_survey_csv`.
- Detail (FR-R04/R05): needs `questionnaireId`, missing → 回答が見つかりません; title, status badge, basic info, answers by `displayOrder`, badges / free-text block / rating value / 未回答.
- Real pagination totals on the response list.
- 状態 / 性別 / 入会後経過期間 filters on the list are `[Prototype-only]`, not built (spec gap 5, `B9`): assert absent. Detail 「この会員の回答履歴」 card (Δ19): newest first, current entry 表示中 and disabled, other entry opens, one scoped `?memberId=` read, pagination 25 / page, error + 再試行する, empty 回答なし.

**U6 — Analytics**

- Target resolution (FR-A02): from detail with `survey_id`; direct without `survey_id` → first questionnaire of the list; dropdown pick writes `survey_id` and re-aggregates; dropdown filter box (server-side `nameQuery`, `%` / `_` literal, 100-char cap, whitespace, IME), no match → 「該当するアンケートがありません」; unknown `survey_id` / list failure → defined error or empty state, CSV disabled.
- 期間 presets → `from` inclusive / `to` exclusive local-midnight (boundary: an answer at 00:00 on the first day of 今月 / 先月 end).
- 入会後経過期間 / 性別 (FR-A01, FR-S006; Δ13): options, URL `tenure` / `gender`, `enrolledFrom` / `enrolledTo` (`YYYY-MM-DD`, JST today − N months, adjacent buckets do not overlap) and `gender` on AGG and EXP, summary order 期間 · ブランド · 店舗 · 会員区分 · 入会後 · 性別, badge count, active highlight, invalid URL value ignored; month boundary awaits PO (§7 Open question 4).
- KPIs: 総回答数 = `submittedCount` (辞退 excluded), 回答率 1 decimal; bars per choice; free-text `samples` with `YYYY/MM/DD` and link 回答一覧で全件を見る → `/surveys/responses?survey_id=<id>`.
- CSV (FR-A04): same filters, BOM, toasts, export permission, disabled with no questionnaire; filename (`B2`).
- Staff scope pinned to own store; Manager all stores / all brands (G-04 データスコープ).

**Data policy** (no seed reset exists, and surveys **cannot be hard-deleted** — a test survey can only end up 無効):

- **Prefix**: every survey the run creates is named `QA-SVY <YYYYMMDD> <short purpose>` (e.g. `QA-SVY 20261022 long-name`).
- **Never edit, disable, or change the visibility of a pre-existing survey.** Those are the live lifecycle templates the member app shows on 入会 / 休会 / 移籍 / 退会. Read-only actions on them (list, detail, responses, analytics) are fine.
- **Trigger uniqueness**: Phase 1 has 4 triggers, and at most one active survey per trigger **and brand scope** (`E-QST-010`: another active survey on the same trigger whose brands intersect; empty = all brands) — enforced on create-as-active, on activation, and on edits of an active survey that change the trigger or the brand scope. JOYFIT-only and FIT365-only surveys can both be active on one trigger. Before the run, note which triggers already have an active survey **and its brands** (read-only, list filter 状態=有効; the ブランド column).
  - On the **shared** dev BE, create test surveys as **無効**. Use a trigger already active for the same brand group to provoke `E-QST-010`. Do not activate a test survey on a trigger that is free for its brand (the member app would start showing it); if a positive "save as 有効" case has no trigger free for the brand it uses, mark it `Block`.
  - On the **local** BE, activating a test survey is allowed, but disable it before the run ends.
  - "No free trigger" (data limitation DL-3 in the List cases, L1 in the Detail cases) now means **no trigger free for the brand the test survey uses**: a trigger held only by a JOYFIT survey is still free for a FIT365 test survey, and vice versa. A test survey with empty brands (all brands) needs a trigger with no active survey at all.
- **Destructive / state-changing cases** (disable, delete question, visibility toggles, two-tab edit) each use their own `QA-SVY` survey, never one another case still needs.
- **Responses**: the run cannot create answers from the CRM. Cases needing answers (`hasResponses`, response detail, analytics bars / samples) use existing answers read-only, or are `Block (B10)` when none exist.
- **Visibility**: toggle only `QA-SVY` surveys, and set every toggle back to ON (使う) at the end.

**Known-gap policy**: a failure matching a `Bn` row in §7 → `Block (Bn)`; an undocumented failure → `NG`.

**Viewport**: 1024×768 (the supported floor) for layout / stress cases; ≥ 1440px for the wide check. Below 1024px is out of scope.

**Account safety**: this feature has no login-form cases, so no wrong-password lockout risk. The 401 cases expire / revoke a session (sign out in another tab, or let the token lapse) — they do not lock the account.

## 10. Suggested order

1. **U1 Survey list** — read-only against existing data; sets the baseline (counts, active-trigger map for the data policy) before anything is created.
2. **U2 Survey form — create** — creates the `QA-SVY` surveys every later unit needs (long-text, many-questions, a choice-format one, a free-text one).
3. **U3 Survey detail** (read-only part) — on both pre-existing and `QA-SVY` surveys.
4. **U4 Store visibility** — on `QA-SVY` surveys; then re-check U3's header-store scoping against what was hidden.
5. **U2 Survey form — edit** — after U4, so a survey with per-store hidden items is also edited; includes reorder, retire choice, two-tab, `E-QST-010`.
6. **U5 Responses** and **U6 Analytics** — read-only; mostly against existing answers (`B10` where none).
7. **Disable cases** (U3 dialog, U1 row) — destructive state change, after everything that needs an active `QA-SVY` survey.
8. **Role-gate cases** for all units — last, so HQ setup work isn't spent under restricted sessions.
9. **Cleanup** — every `QA-SVY` survey 無効, visibility back to all ON.
