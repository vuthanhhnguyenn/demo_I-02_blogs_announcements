# TC -【Fitness CRM】- [Y-07][P2-02][ブランド詳細・基本情報]

**Unit 2 of 5**. Phase 2 (real API) test cases for the brand detail screen (ブランド詳細), route `/brands/[brandGroup]`, **基本情報 tab and screen frame**.

**Scope (in)**: the detail header (h1 + back link 「ブランド管理に戻る」); the tab bar (基本情報 / 費用 / 変更履歴) and its two count badges; role / access gating for all six roles, including the Trainer/Observer access-denied state and Staff's 基本情報-only view (Δ7); invalid routes; the 基本情報 tab: 一般情報 card + 変更 → the shared ブランド編集 Sheet (**entry-point delta only**), and the その他情報 card (作成者 = `Block (G2)`).

**Scope (out)**: the contents of the 費用 tab (Unit 3) and the 費用マスタ Sheet (Unit 4); the contents and paging of the 変更履歴 tab (Unit 5); the full ブランド編集 Sheet field walk, server-side replay of the rename `PATCH` and the list screen itself (Unit 1). This unit checks only the **presence and badges** of the 費用 / 変更履歴 tabs. Also out of scope per the plan: brand 新規登録 (R308), sub-brand body edits, 基本情報を編集 (B6), ADD-09 (B7), the brand status filter / badge (R303), G-01 / Y-02, the backend auto-cutover, login itself.

**Δ ids carried**: Δ2, Δ3, Δ7, Δ10, Δ14, Δ16, Δ17, Δ18 (Δ5 by observation only).
**Known-gap ids carried**: **G2** (作成者 → `Block (G2)`), **D11** (Staff tabs hidden → `OK` per Δ7), **NL-1** (history totals beyond one page never exercised live), **B6** / **R308** (negative-scope absence checks only). B1–B5 are closed: any failure on them is `NG` (regression).
