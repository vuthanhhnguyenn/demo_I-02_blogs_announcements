# TC -【Fitness CRM】- [Y-07][P2-03][費用タブ]

**Unit 3 of 5**: Phase 2 (real API) test cases for the **費用 (Fee) tab** of ブランド詳細, route `/brands/[brandGroup]` (費用 tab). This unit covers:

- the per-slot fee cards: JOYFIT has **4** slots and FIT365 has **1**. Each card can be in the **registered 有効**, **registered 無効** or **未登録** state, and shows **予約中の改定** when a revision is scheduled.
- the 費用マスタ ⋯ menu, the **無効化** confirmation dialog, the **削除** confirmation dialog and the immediate **有効化**
- ［＋登録］ **as an entry point only**
- the **CancelPolicyNote** (MOD-09) and the **費用 tab badge**
- role gating, including server-side replay

**Scope boundary with Unit 4**: the 費用マスタ Sheet's internals belong to `TC -【Fitness CRM】- [Y-07][P2-04][費用マスタ登録・変更].md`. That covers fields, validation, date rules, preview, the 20-row cap and the register-mode body. This doc opens the Sheet only to confirm the entry point (title and target card), and uses it as a **setup tool** to create 予約 / amounts for display cases. It asserts nothing about the Sheet's fields.

**Out of scope** (test plan): brand create (R308); disabling, deleting or renaming the sub-brand itself (only the absence of such controls is checked, TC-010); the 基本情報 editor B6 (only the FIT365 cadence caption is checked, TC-006); ADD-09 (B7); the scheduled-revision auto-cutover batch; the tab bar and the 変更履歴 content (Units 2 and 5).

**Δ ids carried by this doc**: Δ2 (route key, read only), **Δ5, Δ6, Δ7, Δ8, Δ9, Δ10, Δ15, Δ18**, plus Δ12 (F-REV20 display only)
**Known-gap ids carried by this doc**: **G3** (destructive-pair residue), **D11** (Staff tabs hidden → `OK`), **D14** (only charged items shown; decision, not gap), **B6** (cadence caption display only), **B7** (MOD-09 shipped, ADD-09 out of scope), **NL-1** (F-REV20 never exercised live), **DATA** (`Block (DATA)` per Data policy R-2/R-4)

## ⚠️ Read first: data policy for this unit (binding, test plan R-0..R-7)

- **Every write targets the sandbox slot JOYFIT / JOYFIT YOGA only.** The other three JOYFIT slots and FIT365 are **read-only**. On those cards you may open a dialog and press キャンセル, because that writes nothing. **Never press 無効にする / 削除する / ［＋登録］ on them.**
- **Every write case restores the baseline as a numbered step inside the case.** A cleanup note does not count as a restore.
- **予約 used as fixtures** use dates in **2035–2036 only**. Remove them in the same case: one save with the 予約 deleted.
- **無効化 → 有効化**: JOYFIT YOGA only, re-enabled in the same case (R-3).
- **削除 → ［＋登録］ is the one destructive pair** (R-4). It runs **once**, on JOYFIT YOGA, **at the end of this unit** (TC-048 → TC-054, one window). It registers the baseline back. **G3 residue**: afterwards the sub-brand's ¥0 `cardIssueFee` / `maintenanceFee` rows are gone. Record this in TC-054 and hand it to the dev for the API restore. The run is not clean until the dev confirms the restore.
- **FIT365 destructive cases** (TC-056, TC-057, TC-058) are written to the spec and recorded **`Block (DATA)`**.
- **Long-name window** (R-1): stress cases TC-074 and TC-077 – TC-085 and TC-090 run in **one** window. Rename **JOYFIT** (never FIT365) to the fixture, walk every place, then restore to exactly `JOYFIT`. Share the window with Units 1/2/4 (plan Suggested Order step 6).
- **Write log** (R-5): every write case appends `time · account · action · target · before → after` to **§ Write log** at the bottom. Unit 5 checks each line against 変更履歴.
