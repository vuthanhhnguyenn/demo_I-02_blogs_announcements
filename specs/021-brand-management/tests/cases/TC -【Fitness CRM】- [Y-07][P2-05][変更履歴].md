# TC -【Fitness CRM】- [Y-07][P2-05][変更履歴]

**Unit 5 of 5**: Phase 2 (real-API) test cases for the **変更履歴** (change history) tab of ブランド詳細, route `/brands/[brandGroup]` (変更履歴 tab).

**Scope**: the history table (six columns, newest first, one row per changed field), the 対象 values, value formatting, the Japanese action labels for every write type Units 1–4 perform (checked against their **write log**, Data policy R-5), immutability, the tab badge (= server `totalItems`), paging, the empty state, role gating, the real-API failure paths, and the long-value layout of the rows Units 1–4 wrote.

**This unit is read-only.** It writes nothing. The badge-refresh cases (TC-040, TC-041) and the long-brand-name 対象 case (TC-070) are **observations piggybacked on Units 2/3 write steps and the long-name window**. They add no write of their own.

**Out of scope** (per the test plan): every other tab and the list (Units 1–4); ブランド新規登録 (R308); サブブランド本体の操作; 基本情報を編集 (B6); ADD-09 (B7); the scheduled-revision auto-cutover batch; login/session establishment (specs 028/029).

**Δ ids covered**: Δ5, Δ6, Δ7, Δ8, Δ10, Δ11, Δ12, Δ13, Δ16, Δ17.
**Known-gap / decision ids covered**: D9 (flattening), D11 (Staff tabs hidden), R2-D6 (invalidation), R2-D7 (paging), NL-1 (paging never exercised live), G3 (削除 residue), B5 regression (before/after typing, closed), D10 principle (no unprovable count).
