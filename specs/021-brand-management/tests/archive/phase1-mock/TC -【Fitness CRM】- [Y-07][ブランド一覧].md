# TC -【Fitness CRM】- [Y-07][ブランド一覧] (Brand List)

**Scope**: Unit 1 of `specs/021-brand-management/tests/test-plan.md` — ブランド一覧 (Brand List) screen only, route `/brands`, including its search/filter toolbar, table, pagination, row-menu 編集 (edit) action, and the name-edit Sheet. The 費用 (Fee) tab, 変更履歴 (Change History) tab, and brand detail page as a whole are covered by Unit 2 (`TC -【Fitness CRM】- [Y-07][ブランド詳細].md`) and are out of scope here except as a navigation target.

## Source note

Sources used: `specs/021-brand-management/spec.md`, `.cache/fitness-spec/crm/requirements/Y-07.md`, `.cache/fitness-crm-ui/src/pages/brand-list.tsx`, and the supporting mockup components it composes (`role-gated-menu-item.tsx`, `empty-state.tsx`, `filter-result-banner.tsx`, `page-header.tsx`, `field-marker.tsx`) — all present and readable. No sources were missing for this unit.

**Discrepancy flagged**: `spec.md` FR-004 scopes the Trainer/Observer access-denied requirement to the **detail page** only; `Y-07.md`'s 権限マトリクス lists ブランド設定の参照 (view brand settings) as `×` for Trainer/Observer with no list/detail split. The reviewed mockup (`brand-list.tsx`) applies **no** role gate to the list screen itself (only the row's 編集 action is role-gated) — so Trainer/Observer can see brand ID/name in the list per the mockup, but are blocked only at the detail page per FR-004. Cases TC-023/TC-024 test the mockup's actual (list-open) behavior and flag the matrix conflict for resolution; this is not a case failure to log as `NG` on its own — raise it as a spec/requirement-doc clarification.

## Test data reference

Base dataset (`BRANDS` in `brand-list.tsx`) — per FR-015, scope is fixed to exactly these two brands, no new-brand registration in this phase:

| #   | id  | ブランドID (code) | ブランド名 (name) |
| --- | --- | ----------------- | ----------------- |
| 1   | 1   | `joyfit`          | JOYFIT            |
| 2   | 2   | `fit365`          | FIT365            |

**Data limitation**: only 2 rows exist in the spec/mockup's described dataset, and FR-015 fixes this feature's scope to exactly these two — multi-page pagination (page 2+) cannot be reached with real data. Cases involving pagination beyond page 1 are marked to verify only the single-page/edge-disabled state; do not fabricate additional brand rows to force a second page.
