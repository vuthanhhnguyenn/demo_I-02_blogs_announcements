## BUG-021-U1-01 — ブランド名 input silently truncates pasted values at 100 (maxlength), with no message (Medium)

- TCs: TC-061, TC-062, TC-064 (TC-085 is n/a because of this)
- Repro (HQ): /brands → JOYFIT ⋯ → 編集 → paste F-TOK101 (101 chars) into ブランド名.
- Actual: the input has `maxlength="100"`. The pasted value is cut to 100 chars (both `execCommand('insertText')` and `fill`), and no validation message appears. 保存する then sends the cut value: blocked PATCH body `{"displayName":"ZZQA_ABCDEFGHIJ…KLMNO"}` (100 chars). F-JP101 behaves the same way. F-EMOJI100 (100 code points, 101 UTF-16 units) becomes 99 code points. maxlength counts UTF-16 units, so the trailing 😀 is silently dropped.
- Expected (TC-061/062, Δ17, default field constraints): a 101-char value is blocked with a Japanese message under the field that names 「ブランド名」 and the limit (or rejected by the server with that message). The TCs list "silently cut to 100 on paste with no feedback" as NG. For the emoji, client and server should count the same way, and the value should not be altered silently.
- Evidence: out-AU1-12.json (labels 061 fill101 / 061 paste101 / 062 paste101 / 064 emoji, len=100/100/99, err=[]), blockedWrites in that file. Typing past 100 is also stopped by maxlength (TC-066, acceptable there).
