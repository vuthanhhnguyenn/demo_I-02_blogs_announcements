# TC -【Fitness CRM】- [A-01][会員情報を編集] (Member Form — Edit Member Personal Information)

**Scope**: The standalone member **edit form** only (route `/members/{memberId}/edit`, PO spec `A-01` FR-004, screen id `member-form`), including the discard dialog 「変更を破棄しますか？」 and the four non-form page states that replace it (loading, load error, role-denied, withdrawn-member block) — all of which exist only on this route.

**Out of scope** (link-only — a case verifies navigation intent, never the destination): the member **list** `/members` (`specs/019-member-list`, where the 編集 row-menu item and its gating are already covered by TC-045 / TC-046 / TC-107), the member **detail** `/members/{id}` and its tabs (`specs/032-member-detail`), 新規登録 (no create mode exists in Phase 1), 会員種別 / 所属店舗 changes, 個人情報の削除, and ゲートストップ / ブラックリスト / ステータス変更. The 変更履歴 **tab's own UI** is out of scope too, but the **audit record a save produces** is in scope (FR-028, rewritten 2026-09-21) and is read back on that tab.

Driven by [test-plan.md](../test-plan.md) — Unit 1 (Member form). This is a single-unit feature; every FR-001 – FR-033 traces here except the two deliberate non-cases recorded below.

### Data & environment limitations (gate execution — referenced in the affected cases' Notes)

- **This screen writes real personal data on a shared backend.** Every save case must read the member first, keep the whole `personalInfo`, and PATCH the original values back afterwards, confirming an empty diff. Record the member id and the restore result in the case's Notes.
- **A stored non-JP phone no longer blocks a save** _(2026-10-30, A-01 Bug-No19)_ — the API takes E.164, so a `+84…` member is a valid fixture for TC-135. `JF-0000030`'s `+84962150299` was migrated to `09010000030` on 2026-09-23.
- **Never target a member another feature's run is using**, and never touch contract / status / store data from this screen.
- **Test values must be identifiable** — prefix free text with `QA-` where the field's format allows it (フリガナ and 電話番号 cannot take a `QA-` prefix; use valid katakana / JP digits there and note the value used).
- **Long-value data is created by the case itself** (unlike the list screen, this form can type it in). Where a case needs a _pre-existing_ long stored value, the seed has nothing near the caps → **B6**.
- **Account lockout**: repeated wrong-password attempts lock a real Cognito account for ~15 minutes. Run the six-role sweep once, in order; never re-type a password to "retry" a session.
- **Date-sensitive**: 生年月日 is validated against the **real** current date on both sides (today and any future date are rejected). Compute boundaries at run time; do not hard-code them.
