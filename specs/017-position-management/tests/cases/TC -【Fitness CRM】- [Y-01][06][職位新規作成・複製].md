# TC -【Fitness CRM】- [Y-01][06][職位新規作成・複製]

**Scope**: Test Plan **Unit 2** — the position create form (`職位 新規作成`) and its clone mode
(`職位 複製して作成`), at `/positions/create` and `/positions/create?cloneFrom={id}`. Covers the
基本情報 section, the catalog-driven 権限設定 section, CSV role-default seeding, required-field
validation, the unsaved-changes guard, per-role name uniqueness, role gating, and the real-API
behaviours of the create path.

**Out of scope for this document** (per the test plan): the list/preview screen (`Unit 1`,
`[Y-01][05]`), the edit form (`Unit 3`, `[Y-01][07]`), all staff-account screens, change-history
writing (FR-019), role-master editing, CSV enforcement in other features, and system-managed
position UX.

### Run outcome for these gaps (2026-09-17)

- **B3 — CLOSED, in the FE's favour.** The dev API accepts `description` as a JSON **string**:
  `POST /api/v1/admin/positions` with `"description":"B3 smoke test"` returned **`201`** and echoed the
  string back; re-confirmed at 204 and 500 characters, and read back in the list sub-line, the preview
  pane and the edit prefill. **No case in this document is `Block (B3)`.** → **R202 and the Round-1
  T014 fallback are unblocked**; the OpenAPI's `type: object` is a BE documentation defect only, with no
  runtime consequence. Report to the integration owner.
- **B1 — resolved as expected `OK`** (TC-006), but with **new evidence for spec Q5**: the live catalog's
  `can_edit_gate_setting` (入退館管理 → 入退館設定の変更) carries the description
  「ゲートストップ設定の変更を含みます。自店舗のみ」. The BE appears to have **folded** Y-01 FR-006 v2's
  ゲートストップ requirement into that flag rather than dropping it. Q5 may be answerable without a new
  flag — put this in front of the PO before treating the requirement as uncovered.
- **G5 — the smoke found real defects, none of them 4xx-handling false alarms.** The three areas the plan
  named all passed: the 13 helper texts match the catalog verbatim (TC-005), the CSV role defaults are
  correct for all five roles and are catalog-driven, not FE-listed (TC-028…TC-034), and B3 holds. The
  eight bugs found are FE-side (see **Execution summary → Bugs found**) and should go to the integration
  owner as well.

  backend). Counts are asserted as _relative_ ("total increases by exactly 1") or "verify at execution".

  categories**, but do **not** hard-code it: read `GET /api/v1/admin/permissions` at execution and
  compare the form against that response (D-3). A mismatch between this document's "58" and the live
  catalog is a stale document, not a screen defect.

  `NEXT_PUBLIC_APP_ENV=development`. If the menu is missing, check the env var before filing anything.

  fixture (TC-078). Anything left behind stays in the shared master permanently.
- **L5 — no wrong-password cases in this document.** The six Cognito accounts lock for ~15 minutes
  after repeated failures. A forced 401 (TC-064) must be produced by **expiring/clearing the session
  token**, never by failed sign-ins.
