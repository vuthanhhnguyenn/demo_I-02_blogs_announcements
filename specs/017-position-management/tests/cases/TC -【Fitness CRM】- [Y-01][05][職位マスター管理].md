# TC -【Fitness CRM】- [Y-01][05][職位マスター管理]

**Scope**: Test Plan **Unit 1** — the two-pane position master screen at `/positions`: the position
table, name search, the `権限で絞り込む` reverse-permission popover, the filter-result banner,
pagination, the right-hand permission preview pane (category accordion, 重要操作 warning, 割当スタッフ
panel), the row ⋯ menu and its delete confirmation dialog.

> ⛔ **Pre-existing positions are master data and are READ-ONLY.** They may be searched, filtered,
> selected, previewed and paged through, and their ⋯ menu may be **opened** to check an affordance's
> state — but **never clicked through to a destructive action**. Every delete case runs on a
> throw-away position this run created itself (test plan → Data policy).

**Out of scope for this document** (per the test plan): the create/clone form (`Unit 2`,
`[Y-01][06]`), the edit form (`Unit 3`, `[Y-01][07]`), all staff-account screens (a click that lands
on one is verified only as "correct destination + correct pre-filter"), change-history writing
(FR-019), role-master editing, CSV enforcement in other features, and system-managed position UX.

**Data limitations (gate execution)**

- **L1 — no fixed counts, ever.** The master holds an unknown, mutating number of positions. Assert
  **internal consistency** (header badge = footer total; `X-Y` range = page size × page; total
  decreases by exactly 1 after a delete) and **relative deltas**, never an absolute number. The
  spec's "13 initial positions" (Assumptions) describes the _mock_ seed and does **not** apply here.
- **L2 — the catalog is the structural oracle.** Read `GET /api/v1/admin/permissions` at execution
  and derive the expected picker contents, category list and ⚠ set from it (**D-3**, **D-5**).
- **L3 — 「デモ: ユーザー切替」** renders only when `NEXT_PUBLIC_APP_ENV=development`.
- **L4 — cleanup is mandatory** (TC-083): search `ZZQA` and delete every fixture.
- **L5 — no wrong-password cases.** The 401 case (TC-072) is produced by **clearing/expiring the
  session token**, never by failed sign-ins (~15-minute Cognito lockout).
- **L6 — multi-page pagination needs enough rows.** If the master holds fewer rows than 2 pages at
  `limit=25`, the pagination cases cannot run as written — record them `Block` with the observed row
  count rather than creating dozens of throw-away positions to force it.
- **L7 — ⛔ never click a destructive action on a record the run did not create.** TC-059 opens the
  ⋯ menu on a master position and **looks**; it does not click.
