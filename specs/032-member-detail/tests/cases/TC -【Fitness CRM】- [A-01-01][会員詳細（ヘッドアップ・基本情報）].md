# TC -【Fitness CRM】- [A-01-01][会員詳細（ヘッドアップ・基本情報）]

**Scope (Unit 1 of the [test plan](../test-plan.md))** — the member-detail page shell (`A-01-01`: back link / 3-level
breadcrumb, page title, loading / error / not-found / out-of-scope states, tab bar with `?tab=` sync), the four state
banners (gate stop, blacklist [HQ/System only], reservation penalty, pending application), the head-up card
(`A-01-01-a`) with its 3-item summary strip, the header **編集** gate, and the **基本情報** tab (個人情報 / 入会情報 /
家族会員 / 動作確認用アカウント + its confirm dialog / 来館情報 / ゲートストップ / 通知受信設定).

**Out of scope for this document** — the ステータス変更 menu and its sheets (Unit 2), the 会員操作 menu, the gate-stop /
penalty release sheets and the withdrawn-member ⋯ menu (Unit 3), the other nine tab panels (Units 4–10), the member
list (019) and the member-edit form (020). Where a case touches one of them it stops at "the control is present and
opens the right surface". The 変更履歴 label of the test-account rows is checked in Unit 10.

**Re-authored 2026-09-24** from the phase-2 test plan. The 2026-07-28 version was written and executed on the mock
(members `M-000xx`, old FR numbering, the removed 入退館設定 card, 4-channel 通知受信設定, 来館頻度). Surviving TC ids
are kept; new cases start at TC-115. Obsolete cases are listed under [Dropped cases](#dropped-cases).

**Data policy.** The only write this unit makes itself is the 動作確認用アカウント toggle (TC-147 → TC-149, TC-153,

member-form on **F-LONG only**, snapshot → edit → restore, with `QA-MD-<yyyymmdd>` in free text where the field allows.

**Data limitations**

5. Pending applications may only exist after Unit 2 files one — run TC-018 – TC-020, TC-035, TC-042, TC-043, TC-124 then.
