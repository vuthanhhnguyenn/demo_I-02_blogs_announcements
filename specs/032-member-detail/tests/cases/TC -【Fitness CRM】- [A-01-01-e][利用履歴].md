# TC -【Fitness CRM】- [A-01-01-e][利用履歴]

**Scope (Unit 6 of the [test plan](../test-plan.md))** — the **利用履歴** (usage history) tab of the member detail
screen, reached at `/members/{memberId}?tab=usage`. Covers its four cards: **入退館履歴** (gate entry/exit log, date-range +
store filters + pagination), **レッスン予約履歴** (lesson bookings), **オプション利用履歴** (option usage) on the left, and the
sticky right-column **利用状況** (usage summary). Also the tab-level shell rules that apply to it (tabs FR-003 – FR-006),
its role / scope gates and the real-API baseline of test-plan §5.

**Out of scope for this document** — the head-up card, banners, tab bar mechanics beyond reaching this tab and the
基本情報 来館情報 card (Unit 1), the other nine tab panels, the B-01 入退館 screens and the D-01 lesson screens that
produce this data (a case may assert a value, never how B-01 / D-01 produced it), entry/exit **export** (deferred —
only its absence is asserted). The tab is read-only: there is no create / edit / delete flow.

**Authored 2026-09-24** — first version of this unit (no earlier doc).
**Updated 2026-10-14** — 入退館履歴's month picker replaced by a date-range filter + a store filter (tabs Amendment T11): TC-008, 012, 020 – 025, 028, 031, 033, 043 rewritten; TC-084 – TC-093 added.

**Vocabulary the tester must match character-for-character**

- Card titles: `入退館履歴` / `レッスン予約履歴` / `オプション利用履歴` / `利用状況`
- 入退館履歴 columns: `日時` / `店舗` / `種別` / `認証方法`; 種別 badges `入館` (info colour, log-in icon) / `退館` (default
  colour, log-out icon); 認証方法 `QRコード` / `ICカード` / `顔認証` / `手動解錠`
- レッスン予約履歴 columns: `日付` / `レッスン名` / `担当` / `状態`; states `受講済み` (success) / `キャンセル` (warning) /
  `予約中` (info) / `欠席`
- オプション利用履歴 columns: `日付` / `店舗` / `オプション名` / `回数` (right-aligned); cell `{count}回`
- 利用状況 items: `今月来館回数` (spec) / `よく利用する時間帯` / `よく利用する店舗` / `レッスン予約数（今月）` /
  `オプション利用数（今月）`; delta `前月比 +{n}回` / `前月比 -{n}回`
- Empty month (all three tables): `この月のデータはありません。`
- Month picker trigger: `{YYYY}年{M}月` (no zero padding); popover year `{YYYY}年`, months `1月` … `12月`
- Footer: `{n}件` + `前へ` / `次へ`

**Prototype sample (shape only)** — `ENTRY_EXIT_HISTORY` 2026/03 at JOYFIT渋谷店 / JOYFIT新宿店 with ICカード / QRコード;
`LESSON_HISTORY` ヨガ初級 / HIIT / ピラティス / ヨガ中級 with 田中先生 …; `OPTION_USAGE_HISTORY` 水素水 / プロテインサーバー /
シャワールーム優先利用, 1回 each. Values on dev differ.

**Data limitations**

1. Usage data cannot be created from the CRM → every row-shape case depends on a fixture; long-value cases use the
   **longest name that already exists** on dev. Creating a long store / lesson / option master would touch shared
   master data and is not done — if the longest real value is short (< 20 full-width chars), the case records the
   length used and is `Block (fixture: long master name)` for the extreme variant.
2. Multi-page cases need > 25 rows in one month (F-MANY\*) — likely rare for bookings / option usage.
3. The month-edge case (TC-031) needs a real record near midnight JST on a month boundary.
4. Delta cases need members whose current/previous month relation is +, 0 and − **on the run date**; the current month
   is partial, so the classes shift as the month progresses — pick them on the day.
5. XSS (TC-083) needs a master name with markup — none is expected → `Block (fixture)` unless found.
