# TC -【Fitness CRM】- [A-01-01-f][ポイント履歴]

**Scope (Unit 7 of the [test plan](../test-plan.md))** — the **ポイント履歴** (point history) tab of the member detail
screen, reached at `/members/{memberId}?tab=points`. Covers its two cards: the brand-named history table
**{ポイント名}履歴** (ENJOYポイント履歴 / ベアレージポイント履歴 — unified 獲得 / 消費 rows, period filter — month picker or 期間指定 date range —, 日付 / 種別 sort)
on the left, and the sticky right-column **ポイントサマリー** (残高 / 期間内獲得合計 / 期間内消費合計 / 失効予定). Also the
tab-level shell rules that apply to it (tabs FR-003 – FR-006), its role / scope gates, the real-API baseline of
test-plan §5 and the cross-check with Unit 10's manual refund.

**Out of scope for this document** — the head-up card, banners and tab bar mechanics beyond reaching this tab (Unit 1),
the other nine tab panels, the **ポイント手動返還** dialog itself (Unit 10 — this doc only asserts that the refund it
records shows up here, and that no refund control exists on this tab), the point-discount return inside 休会申請
(Unit 2), and the mobile-app / campaign processes that earn or spend points (a case may assert a value, never how it
was produced). The tab is read-only: there is no create / edit / delete flow.

**Authored 2026-09-24** — first version of this unit (no earlier doc). **Revised 2026-10-15** — 任意期間指定 added per `A-01 FR-011` (tabs FR-030-a): TC-039 reinstated, TC-075 – TC-082 new.

  success) / `期間内消費合計` (`-{n}pt` destructive) / `失効予定` (`{n}pt（YYYY/MM/DD）` muted, full-width parentheses)

**Data limitations**

1. Point data cannot be created from the CRM beyond Unit 10's 1 pt refund → every row-shape case depends on a fixture;
   long-value and max-digit cases use the **longest / largest value that already exists** on dev and record it. If
   nothing long or large exists, the extreme variant is `Block (fixture)`.
2. The refund cross-check (old TC-051 / TC-052) moved to Unit 10 TC-059 / TC-061 — see _Moved cases_; this run recorded
   the 残高 baselines for it.
3. The month-edge case (TC-036) needs a real record near midnight JST on a month boundary.
4. F-PTMANY may not exist (many transactions in one month is rare) → TC-029, TC-064 `Block (fixture)`.
5. XSS (TC-074) needs markup in a 事由 — only possible if Unit 10's 返還理由 is echoed as 事由 (U7-11) and the run is
   allowed to type such a reason; otherwise `Block (fixture)`.
