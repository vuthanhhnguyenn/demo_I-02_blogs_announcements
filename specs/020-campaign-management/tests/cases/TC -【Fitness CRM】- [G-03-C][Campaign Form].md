**Spec-vs-mockup conflicts found and flagged in-line (oracle = spec intent, per SKILL.md):**

1. **FR-003 auto-grant gender targeting.** FR-003 requires per-option gender targeting (each
   auto-granted option independently carries its own optional gender list), explicitly
   _replacing_ "the current campaign-wide gender condition applied to a flat option-identifier
   list." The reviewed mockup (`campaign-form.tsx` L805–864) renders exactly the pattern FR-003
   says to replace: one campaign-wide `性別条件` checkbox group (男性/女性/その他) that is
   independent of, and applies uniformly across, the `自動付与オプション` checkbox list — there
   is no per-option gender picker. TC-071 writes the case to FR-003's intent and records
   whichever the running app actually implements as a finding.
2. **Discount-row option picker not rendered in the reviewed mockup.** The `DiscountRow` type
   (`campaign-form.tsx` L98–103) carries a `targetId` field, and FR-002/the Edge Cases section
   require a discount row targeting an option to identify _which_ option and reject an empty
   selection — but no JSX control in the reviewed file binds any input to `targetId` (grep
   confirms zero bindings). TC-045 is written to the spec's intent; the exact control/label to
   interact with must be confirmed against the live app since the mockup doesn't show it.
3. **Edit-mode title.** The mockup hard-codes the page title to `キャンペーン 新規登録` (New
   Campaign Registration) with no visible edit-mode branch. Neither spec.md nor the mockup
   states an edit-specific title. TC-082 records this as an open question rather than asserting
   unconfirmed exact copy.
