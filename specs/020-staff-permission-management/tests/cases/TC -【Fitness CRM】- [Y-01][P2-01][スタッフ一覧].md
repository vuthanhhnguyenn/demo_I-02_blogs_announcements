## Phase 2 execution context (read before running)

- **Real backend.** These screens call `https://api.dev.fitness-v2.okamoto-hd.com/api/v1/…` **directly from the browser** (cross-origin), not `localhost:3000/api`. Point request watchers at that host and capture every 4xx/5xx body — for most cases below the response body _is_ the evidence.
- **🚨 The dev backend holds REAL staff records — they are not fixtures.** Treat every account you did not create yourself as production data.
  - **Read-only / display cases** (list rendering, search, filter, sort, pagination, badges, layout, tab visibility, viewing a detail or history) may use **any** account, real dev staff included.
  - **Data-changing cases** (create, edit, 無効化, 有効化, 削除, 再招待, magic link, session revoke) may act **only** on an account you invited yourself during this run, or on one of the five seeded test accounts below. **Never on a real dev staff record.**
- **Seeded test accounts** (user-provided 2026-09-18, `Password@123` for all five) — **sign in as these**, not the older `src/lib/auth/demo-users.ts` set:

  | Role        | Address                            |
  | ----------- | ---------------------------------- |
  | Headquarter | `lodu4289+test_hq@gmail.com`       |
  | Manager     | `lodu4289+test_manager@gmail.com`  |
  | Staff       | `lodu4289+test_staff@gmail.com`    |
  | Trainer     | `lodu4289+test_trainer@gmail.com`  |
  | Observer    | `lodu4289+test_observer@gmail.com` |

- **These five are also your login identities**, so an irreversible or access-removing action on one destroys the role pass that still needs it. For 無効化 / 有効化 / 削除 / session revoke, **invite a fresh account in Unit 2 and target that** — never a seeded account, never a demo-user account, never a real record.
- **No `test_system` account was seeded.** System-role cases have no safe identity: run them as `lodu4289+1@gmail.com` **read-only**, or mark them `Block — no safe System account`. **Never attempt the last-system-admin guard cases against a real System account** — locking the environment out is not recoverable from the UI.
- Every role-gated case must be run **as** the named role, not inferred from another role's result.
- **No seed reset.** Destructive cases (無効化 / 有効化 / 削除) are irreversible against shared dev data. Use the fixtures created in Unit 2, never a demo-user role account, and never the account you are currently signed in as.
- **Account lockout.** Cognito locks an account for ~15 minutes after repeated bad passwords — negative-login cases (none in this unit) must use a throwaway email.
- **Grading.** `NG` = the UI misreports what the backend did (success toast for a call that failed, error body swallowed into a stock message, list not reflecting a completed mutation, wrong gating, unmapped enum rendered raw) or a confirmed rule/gating defect against the 権限マトリクス. `Block` = the endpoint is absent/unimplemented, the data cannot be produced through any in-scope screen, or the check needs a raw API call the harness cannot issue. **Do not carry a Phase 1 `Block` forward unexamined.**

### Endpoints this unit exercises

| Action                                   | Endpoint                                   | Notes                                                                                                                                                                                                                                                  |
| ---------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Load / search / filter / sort / paginate | `GET /api/v1/admin/staff`                  | Params: `page`, `limit`, `keyword`, `emailDomain`, `role`, `positionId`, `storeId`, `status`, `isActive`, `inviteStatus`, `area`, `sort`, `order`. Responses `200 / 401 / 403`                                                                         |
| 無効化                                   | `POST /api/v1/admin/staff/{id}/deactivate` | Body `DeactivateStaffRequestDto` — **`deactivatedReason` is required**; `400` is returned for a missing or empty reason (E-VAL-001). `403` not HQ (E-AUTH-103). `404` not found (E-STF-001). `422` cannot deactivate the last system admin (E-STF-007) |
| 有効化                                   | `POST /api/v1/admin/staff/{id}/reactivate` | No body. Responses `200 / 401 / 403 / 404`                                                                                                                                                                                                             |
| 再招待                                   | `POST /api/v1/admin/staff/{id}/reinvite`   | `200` re-invited, new token issued. `403` caller is not HQ (E-AUTH-103). `404` not found (E-STF-001). `422` staff already onboarded (E-STF-003) or deactivated (E-STF-004). `502` Cognito user creation failed (E-STF-005)                             |
| 削除                                     | `DELETE /api/v1/admin/staff/{id}`          | `200` soft-deleted **and PII masked**. `403` not HQ (E-AUTH-103). `404` not found or already deleted (E-STF-001). `422` cannot delete the last system admin (E-STF-014)                                                                                |

## Open questions raised by this document

1. **G1 (TC-005, TC-006)** — is Trainer/Observer denial a route 403, or is a disabled sidebar entry considered sufficient? The two give different expected results for the same case.
2. **G7 (TC-097)** — where does the user land after deleting, and does the account vanish from the list or render with a 削除済み treatment? The prototype models no outcome.
3. **G9 (TC-090)** — is the deactivation reason optional (spec, prototype) or required (`DeactivateStaffRequestDto`)? The list dialog offers no field either way.
4. **有効化 (TC-083, TC-092–TC-094)** — needs an FR in `spec.md`; currently authored against the prototype alone.
5. **TC-068** — the intended sort order for the ステータス enum column is unspecified.
6. **TC-100** — the intended default 表示件数 (the mockup says 50; other list screens in this CRM use 25).
7. **TC-121, TC-123** — the URL-state contract for this screen (param names, reload/back-forward persistence) is unspecified.
