# TC -【Fitness CRM】- [Y-01][スタッフ一覧] (Staff List)

**Scope**: Unit 1 of the [test plan](../test-plan.md) — スタッフ一覧 (Staff List) screen, app route `/staffs`. Covers FR-001, FR-002, FR-003, FR-004, FR-005, FR-006 plus the list-triggered quick actions for deactivate/delete/resend-invitation (FR-018/FR-019/FR-006) and the entry point to Staff Registration (FR-007). Out of scope per the plan: the Staff Registration form itself, the Staff Edit form, the Staff Detail screen's info/history tabs, and any position-master / FC-company / store-master administration screens.

## Source note

- Spec: `specs/020-staff-permission-management/spec.md` — User Story 1 (all acceptance scenarios), Edge Cases (single-store header context; invited-row filtering), FR-001…FR-006, FR-018/FR-019 (list-quick-action portion), Key Entities.
- Requirement doc: `.cache/fitness-spec/crm/requirements/Y-01.md` — FR-001 (list display/search), 6-role definitions, permission matrix (権限マトリクス).
- UI mockup: `.cache/fitness-crm-ui/src/pages/staff-list.tsx` — exact Japanese labels, column set, filter controls, row-menu actions, sort/pagination behavior, empty states.
- Shared checklists: `tests/checklists/common-function-checklist.md`, `tests/checklists/common-gui-validate-checklist.md`. Two rows were added to the shared checklists while authoring this unit (see **Checklist additions** below) — apply them to future list-screen TC docs too.
- All three sources were available; no `Block — needs spec/mockup` cases were required.

**Data limitations**:

1. Only 12 seed rows exist across all roles/statuses in the reviewed mockup. At the default page size (50), all 12 rows fit on one page — pagination cases involving a second page, disabled prev/next at real boundaries, and the >7-page ellipsis pattern cannot be exercised without a larger seeded dataset. Affected cases are marked below and should be re-verified once the app's actual mock DB seed size is known (switch page size to 25 with ≥26 rows if available).
2. The 詳細フィルター store-filter dropdown's static option list (`JOYFIT新宿店`, `JOYFIT24梅田店`, `JOYFIT YOGA渋谷店`, `FIT365八潮店`, `FIT365仙台店`, `JOYFIT+六本木店`) does not exactly match every `stores` value used in the sample rows (e.g. STF-002's store is `JOYFIT24新宿店`, not the filter's `JOYFIT新宿店`) — an apparent naming inconsistency in the reviewed prototype. Store-filter cases below use only the two names that match verbatim in both places: `FIT365八潮店` and `FIT365仙台店`. The mismatch itself is flagged as an open question, not silently resolved.
3. The requirement doc (`Y-01.md`) permission matrix marks Trainer/Observer list access as "×", while the spec (FR-004) and the mockup both explicitly include Trainer/Observer in "self-only" visibility. Cases below follow the spec/mockup (self-only, not fully blocked) per the oracle precedence rule, and this doc-vs-spec difference is noted here rather than resolved silently.
