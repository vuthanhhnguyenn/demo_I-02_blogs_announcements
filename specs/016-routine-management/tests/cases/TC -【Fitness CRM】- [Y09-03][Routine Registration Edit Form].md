# Test Cases: Routine Registration / Edit Form (Y09-03) — Phase 2 (real API)

> Driven by [test-plan.md](../test-plan.md), unit **Y09-03**. Covers `/routines/create` and `/routines/[id]/edit` (one shared form): basic info, thumbnail section, exercise composition (picker, reorder, remove, HQ comment), set table (add / copy / remove / numeric rules), publish switch, save outcomes, unsaved-changes guard, role gating, real-API behaviour, layout under long values. Also the landing half of 複製 (FR-014: the user arrives on the copy's edit form).
> **Out of scope here**: the list (Y09-01) and detail (Y09-02) screens beyond reading back saved values; routine category management (Phase 2, Delta #1); Y-08 exercise screens; the mobile app.

## ⚠️ Data-safety rule — read before executing

The dev backend (`https://api.dev.fitness-v2.okamoto-hd.com`) is **shared** and never reset.

- Create / edit / publish / duplicate / delete freely — **only on routines this run created**, all named with the prefix `QA-Y09 <YYYYMMDD>` (use the execution date).
- **Never open the edit form of a pre-existing routine** and never publish/unpublish or delete one. Publishing changes what members see in the app.
- Cleanup is **not required** (agreed for this feature). List what was left in **Data left on the shared backend** at the end.
- If a case cannot run without touching pre-existing data, record `Block (ENV)` — do not improvise.
