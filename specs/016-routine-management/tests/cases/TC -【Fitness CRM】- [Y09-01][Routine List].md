# Test Cases: Routine List (Y09-01) — Phase 2 (real API)

> Driven by [test-plan.md](../test-plan.md), unit **Y09-01**. Covers `/routines`: header + count, columns, keyword search, category / status filters, active-condition count, result banner + 条件をクリア, sort, paging, empty states, the row action menu (編集 / 複製 / 公開する・非公開にする / 削除) and its dialogs, role gating, real-API behaviour (totals, races, 401), layout under long values.
> **Out of scope here**: the form (Y09-03) and detail (Y09-02) beyond navigation; routine category management (Phase 2, Delta #1); the mobile app.

## ⚠️ Data-safety rule — read before executing

The dev backend (`https://api.dev.fitness-v2.okamoto-hd.com`) is **shared** and never reset.

- Publish / unpublish / duplicate / delete **only routines this run created** (prefix `QA-Y09 <YYYYMMDD>`). Pre-existing rows are **read-only**: search, filter, sort, page, open detail — never open their row menu actions.
- Totals are read live at the start of each case; never assert a fixed number the case did not create.
- Cleanup is **not required**; list what was left at the end.
