# Test Cases: Routine Detail (Y09-02) — Phase 2 (real API)

> Driven by [test-plan.md](../test-plan.md), unit **Y09-02**. Covers `/routines/[id]`: header (title, code, status badge, 複製 / 編集 / 削除), 「基本情報」 tab (fields, thumbnail gallery, status card with publish toggle — Delta #4), 「エクササイズ構成」 tab (totals, exercise cards, set table, HQ comment, Y-08 link), delete dialogs incl. the published-routine block (Delta #3), role gating, real-API behaviour, layout under long values.
> **Out of scope here**: the form itself (Y09-03 — this doc only checks that 編集/複製 land there), the list (Y09-01), routine category management (Phase 2), Y-08 exercise detail content (D12), the mobile app.

## ⚠️ Data-safety rule — read before executing

The dev backend (`https://api.dev.fitness-v2.okamoto-hd.com`) is **shared** and never reset.

- Publish / unpublish / duplicate / delete **only routines this run created** (prefix `QA-Y09 <YYYYMMDD>`).
- Pre-existing routines may be **viewed** (TC-010, TC-012) — never publish, unpublish, duplicate-then-edit, or delete one.
- Cleanup is **not required**; list what was left at the end.
- If a case needs pre-existing data in a state that does not exist, record `Block (ENV)`.
