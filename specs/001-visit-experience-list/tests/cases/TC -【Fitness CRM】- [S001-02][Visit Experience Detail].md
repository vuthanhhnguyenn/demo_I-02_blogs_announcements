**Spec-vs-mockup gaps and notable findings flagged here (and again inline in the affected cases' Notes)** — carried over from `test-plan.md` §4/§6, plus a few found while authoring this doc:

1. **Status label wording differs from `spec.md`.** `spec.md`'s state table and FR-005 use the pre-v5 labels (確認待ち / BL照合中) for the info-missing/bl-match states. The mockup — consistent with `C-01.md`'s v5 changelog — uses 申請者への確認待ち / BL照合結果あり・確認待ち. Cases use the mockup's current wording and flag the drift; **verify against the live app**.
2. **7 states exist, not 5.** `spec.md`'s design table (§ UI Mockup Summary) lists only 5 variants (default/info-missing/bl-match/visiting/completed); the mockup additionally implements **enrolled** (入会申請済) and **cancelled** (キャンセル) as first-class variants, each covered in spec prose (Edge Cases + FR-018) even though absent from the table. All 7 are tested below.
3. **Enrolled-state action button contradicts FR-018.** FR-018 states 入会申請済/キャンセル show "no actionable buttons." The mockup's `cancelled` variant matches this, but `enrolled` renders an active `入会申請の詳細を確認 →` link button — and it is **not role-gated** (a plain `Button`, unlike the `RoleGatedButton` used everywhere else), so it stays active even for Trainer/Observer. Tested as-built with the contradiction flagged (TC-037, TC-043).
4. **B-01 card scope differs from FR-014.** FR-014 says the B-01 入退館連携情報 card shows "when the reservation is in the visiting or completed state." The mockup's `showB01Card` also includes **enrolled**. Additionally, for the enrolled state the card omits 退館時刻 (exit time) even though the underlying mock data already has one (the applicant has left) — a possible real gap, not just a doc/mockup wording difference. Flagged in TC-068.
5. **来店詳細情報 shows 2 fields not in FR-006's list.** FR-006 documents only 来店予定日時, 見学許可発行日時 (conditional), 見学終了日時 (conditional). The mockup additionally shows 入会申請日時 (enrolled) and キャンセル日時 (cancelled) conditionally. Tested as-built (TC-062/063) with the spec gap flagged.
6. **Info-missing action-section's missing-items list may be static, not computed.** The mockup's disabled-button block always lists the same 3 literal items (電話番号/住所/顔写真) regardless of which fields are actually missing on that specific record. Written as an open-question case (TC-032) rather than assuming either behavior.
7. **Permit-issuance operator name may be hardcoded in the mockup.** The mockup's `handlePermit()` always records the fixed string "管理者A" as the timeline operator, not the actual logged-in user. Written as a verify-against-live-app case (TC-051) rather than assumed either way.

## Test data reference

The 7 named mock objects in the mockup (`MOCK_BASE`/`_INFO_MISSING`/`_BL_MATCH`/`_VISITING`/`_COMPLETED`/`_ENROLLED`/`_CANCELLED`) — used to reason about per-state branching _logic_, not as a guarantee of the live seed's actual records. **At execution, use whatever real reservations exist in each of the 7 states in the live app.**

| Variant      | Status label (mockup)    | Key differentiators                                                                                       |
| ------------ | ------------------------ | --------------------------------------------------------------------------------------------------------- |
| default      | 申込受付                 | All personal info present; facePhotoRegistered=true; blMatch=false; approvedAt/visitStartAt/etc. all null |
| info-missing | 申請者への確認待ち       | phone="", address="", facePhotoRegistered=false                                                           |
| bl-match     | BL照合結果あり・確認待ち | blMatch=true, blMatchReason="氏名＋生年月日一致"                                                          |
| visiting     | 見学中                   | approvedAt, visitStartAt, b01EntryAt all set; visitEndAt null                                             |
| completed    | 見学終了                 | approvedAt, visitStartAt, visitEndAt, b01EntryAt, b01ExitAt all set                                       |
| enrolled     | 入会申請済               | all of completed's fields plus enrolledAt set                                                             |
| cancelled    | キャンセル               | cancelledAt set; all visit-progress fields null                                                           |

**Data limitations**: exact live reservation IDs in each of the 7 states are unknown from spec/mockup alone — verify at execution that at least one real record exists per state (per the plan's cross-unit dependency on S001-01 seed data). A record combining bl-match + info-missing simultaneously (TC-021) and a record with a genuinely long name/address/BL reason (TC-075–077) may not exist in the live seed — marked `Block`/data-dependent below rather than fabricated.
