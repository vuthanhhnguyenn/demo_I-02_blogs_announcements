**Spec-vs-mockup gaps and notable findings flagged here (and again inline in the affected cases' Notes)** — carried over from `test-plan.md` §4/§6:

1. **Status label wording differs from `spec.md`.** `spec.md`'s status table and FR-008 use the pre-v5 labels (確認待ち / BL照合中). The mockup — consistent with `C-01.md`'s own v5 changelog (260624_v5) — uses the updated labels 申請者への確認待ち / BL照合結果あり・確認待ち. Cases below use the mockup's (and C-01.md's) current wording as the verbatim string to check, and flag the doc-drift rather than silently picking one. **Verify against the live running app**, since the app may have been built from either version.
2. **A 5th filter (BL照合) exists in the mockup but not in `spec.md`'s FR-004/Key-Entities.** `spec.md` documents only 4 filter dimensions (status/brand/store/date-range); the mockup adds a BL照合 select (全件 / 要注意者のみ). Cases below test it as a 5th independently-combinable filter and flag the spec gap.
3. **Observed pagination default page size is 50, not 25.** (Differs from the unrelated finding on the Brand list screen, where 25 is correct — do not assume either default carries over between screens.) Test against the live app's actual default rather than assuming.
4. **No column sort exists on this table** — unlike some sibling list screens in this codebase. Written as an explicit negative check (TC-051) rather than skipped.
5. **This feature is already live-implemented**, not just a design-prototype mockup (`src/app/(private)/visit-experiences/page.tsx` + API routes + `visit-experience.seed.ts`). Expected results below are grounded in spec/mockup intent (the oracle) but should be run against the real app; log `Block` only for the specific data-limited items noted per-case, not broadly for "mocked backend."
