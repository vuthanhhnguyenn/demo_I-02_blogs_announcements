**Data limitations**

- **Status transitions are irreversible** (no way back to 準備中): run the ステータス変更 walk and both LV-04 toast cases **last in this unit**, on FX-STATUS-1 / FX-LONG-J / FX-LONG-T only. Never change the status of a pre-existing store; the API-refusal cases for Manager/Staff send the **current** status value.
- 閉店 cannot be reached from the UI (only 閉店日 + the daily batch): 閉店-state cases depend on a pre-existing closed store → `Block (no fixture)` if none.
- ≥100 history rows (LV-19 rows) need a store with a long history → `Block (no fixture)` if none.
- LV-14 J/T variants need a 255-char 【QA】 FC company, allowed only if Y-03 can deactivate it → otherwise only the "longest existing" case runs.
- Counts are never hard-coded: the backend is shared and not reset. History row counts are asserted only for rows the case itself creates.
- Staff accounts may sit on 未割当 職位 with 0 permissions (memory): if Staff cannot reach `/stores`, fix the 職位 via Y-01 or mark Staff cases `Block (account provisioning)`.
