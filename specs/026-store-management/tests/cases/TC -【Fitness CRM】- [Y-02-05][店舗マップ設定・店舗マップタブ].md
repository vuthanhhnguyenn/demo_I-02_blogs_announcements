# TC -【Fitness CRM】- [Y-02-05][店舗マップ設定・店舗マップタブ]

**Scope (test plan unit 8 — Store map):** the read-only 店舗マップ tab on the store detail (`/stores/[id]`, 店舗マップ tab), the 店舗マップ設定 screen (`/stores/[id]/map`), and the same screen entered with no store in the address (`/stores/map`). Entry points from E-01 (locker list / locker form) are tested only as navigation into this screen.

**Out of scope (per test plan §1):** creating / editing / deleting cabinets, slots, shapes or location codes (E-01); multiple floors, drawn areas, zoom/pan/snap (removed at prototype `e5501a3`); slot status / occupancy on the map (E-01 FR-016 display half); store-page CMS editing (I-01) — only SC-008 preservation is checked; the store's 変更履歴 tab rendering (unit 3); viewports below 1024px.

**Data limitations (verify at execution):**

- **DL-1** Cabinets come from E-01. If E-01 cannot create `【QA】` cabinets on a fixture store (or cannot delete them afterwards), every case needing cabinets on FX-MAP falls back to S-OWN (positions only, restore after) or is Block (no fixture).
- **DL-2** LV-29's > 100 cabinets almost certainly cannot be created on the shared backend → expect **Block (no fixture)** for TC-154 unless E-01 offers bulk create + delete. TC-155–TC-158 need only ~15–20 cabinets.
- **DL-3** Long cabinet names depend on the E-01 location master's own limit; record the length actually reached.
- **DL-4** Full-width file names are capped by the OS at 255 bytes, so LV-17 (J) cannot reach 255 characters; record the length used.
- **DL-5** The 409 case needs a second HQ-level session (System account, separate browser profile).
- **DL-6** Counts (`{n}棟`, 配置済み / 未配置) are verified against the E-01 locker list for the same store at execution time, never hard-coded.
- **DL-7** Image delete (TC-054) is destructive; run it after every case that reads the saved image.
