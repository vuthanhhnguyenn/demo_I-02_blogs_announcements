# TC -【Fitness CRM】- [Y-02-02][店舗登録・編集]

**Scope**: Test Plan **Unit 2 — Store form**: 店舗新規登録 (`/stores/create`) and 店舗編集 (`/stores/[id]/edit`), one component in two modes. Covers the 基本情報 card (Phase 1 fields), the weekly hours table (editable on create; read-only on edit under **B13**), the dev-added 店舗写真 card, 備考, validation and server errors, the 店舗コード warning + change dialog, the brand lock, the permission wall and restricted-Staff mode, the unsaved-changes guard, and the real-API behaviours (E-STR-002 / E-STR-006 / E-FC-002, over-limit values, explicit nulls, partial failure, the **status-reset live check**). **This unit creates the shared fixture set** (FX-BRAND, FX-FIT365, FX-STATUS-1, FX-LONG-J, FX-LONG-T) that units 3–8 reuse.

> ⛔ **Stores cannot be deleted.** Every store this run creates is permanent. Create **only** the five fixtures below, and only after TC-001 confirms they do not exist yet. Never edit a store without the `QA-P2-` prefix — except the Staff account's own store, for reversible writes that each case restores. Pre-existing stores may be **opened** read-only (e.g. the 休業中 / 閉店 brand-lock check) and left via キャンセル with nothing touched.

### Data limitations

- **L1 — no fixed counts.** Never assert the list's total; assert that the created store is findable by its code.
- **L2 — Staff own store is pre-existing.** Allowed: reversible writes to 店舗名 / 住所 / 電話番号 and photos, each restored inside the same case. Never touch its status, brand or 1DayPass.
- **L3 — Staff provisioning.** If the Staff account sits on 未割当 職位 (0 permissions) every PC-D case is `Block (account provisioning)` unless its 職位 is fixed via Y-01 first.
- **L4 — request inspection.** The harness's `startWatchRequests` only sees GETs; patch the scratchpad copy to watch POST / PATCH / PUT for every PC-I case. Request rewriting / aborting uses `page.route`.
- **L5 — FC companies.** The longest active company and an inactive company are read from Y-03 at execution; no FC company is created unless Y-03 can deactivate it afterwards.
- **L6 — 休業中 / 閉店 data.** Only pre-existing stores can be in 閉店 (closure happens through 閉店日 + the daily batch). They are opened read-only.
- **L7 — no lockout cases.** The 401 case clears the session; there are no wrong-password steps.

1. TC-001 → create-form structure and validation (TC-002–TC-032; TC-031 after FX-BRAND exists).

5. Confirm restorations: FX-BRAND = `QA-P2-BRAND`, JOYFIT/JOYFIT24, original name; FX-FIT365 code `QA-P2-FIT365`; Staff own store values and photos.
