# TC -【Fitness CRM】- [A-01-BL-C][Blacklist Detail]

**Unit C** of the Blacklist Management test plan — the ブラックリスト詳細 screen (`/members/blacklist/{blacklistId}`) with its ブラックリスト解除 confirmation dialog and the released-entry rendering reached by direct URL.

**Scope**: access control, header, member head-up card, 登録情報 / 未納金 cards, status card, release flow and its guards, released-entry rendering, member invariants (FR-066, FR-067), loading/error and layout at 1024px.

**Explicitly out of scope** (per [test-plan.md](../test-plan.md) §1):

- The list (Unit A) and the Sheet (Unit B) — used only to create `QA-BL-` entries and to confirm absence/reappearance.
- The member detail (`A-01-01`) beyond the status-unchanged assertion (FR-066) and the 会員詳細を開く navigation.
- 照合条件 card, history card, level — not built by decision (Q-02, Q-06); absence cases only.

## Test-data reference & limitations

- **Pre-existing entries are read-only**: open them to read fields, never release, edit or re-register. Release is irreversible for that record.
- **Release cases use only run-created entries.** For every destructive case register its own throw-away member + entry first (Unit B flow), prefix **`QA-BL-<yyyymmdd>-C<n>`** (about 8 entries: C1–C8). **Capture each entry's detail URL before releasing** — the post-release redirect and FR-033 remove every other way back.
- Variants needed from live data (verify at execution, else Block "variant missing" or PC-E): entry with unpaid > 0 and 0; entry with and without legacy code / current main contract / primary store; BAT-019 entry (B2); entry with a null registering actor.
- Throw-away members stay 仮 — the withdrawn-member variant of FR-066 cannot be produced; no throw-away can be forced into 退会.
