## 2. Fix plan — work packages (do in this order)

Each package is one commit. `npm run type-check && npm run lint` after each. Estimates are for one dev.

### WP1 — Shared 401 handling (D01A-04, D01B-06) · High · ~1h

`src/lib/services/ClientRequest.service.ts` `#handleRefreshToken`: after `#refetchRequest(...)`, if the retried response is **still 401**, call `await handleLogout({ sessionExpired: true })` before returning. Do the same in the `this.#promise` branch (second concurrent request). This is shared with every screen — change is 4 lines, but smoke one other integrated screen (e.g. `/staffs`) after.

Re-verify: Playwright `route` the bookings GET → 401 (A-077) and the create POST → 401 (B-043). Expect `window.location` → `/login?variant=session-expired&redirect=…`.

### WP2 — In-flight guards (D01A-03, D01B-03) · High/Med · ~1h

Pattern already in the repo: `isSubmittingRef = useRef(false)` (`franchise-companies/[id]/_components/unlink-store-dialog.tsx`).

1. `session-memo-card.tsx` `handleSave`: add `isSavingRef`; set true before `mutate`, reset in `onSettled`. Also pass `disabled={isPending}` through (already there) — the ref is what closes the one-tick window.
2. `add-reservation-dialog.tsx`: replace `const [isSubmitting, setIsSubmitting] = useState` with a ref **plus** state (ref for the guard, state for the button's disabled look).
3. `cancel-reservation-dialog.tsx` `handleConfirm`: same ref guard; reset in `onSettled`.

Re-verify: A-069, B-039, B-057 — `route` with `delayMs`, 3 clicks in one tick, `getRouteCallCount === 1`.

### WP3 — Refetch after refusal + dialog state resets (D01B-04, D01B-10, D01B-11) · Med · ~1.5h

1. `add-reservation-dialog.tsx` `handleConfirm`: move `invalidateBookingQueries` out of the `succeeded > 0` branch — always invalidate after the loop (also the remaining-count query). Keep failed chips in the dialog (D2) but the seat `<Select>` must rebuild from the refetched `seats` prop.
2. `cancel-reservation-dialog.tsx`: use `onSettled` for `invalidateBookingQueries`; keep `onOpenChange(false)` in `onSuccess` only.
3. `cancel-reservation-dialog.tsx`: reset `cancelledBy` to `'member'` when `open` turns true (`prevOpen` pattern already used in `add-reservation-dialog.tsx` line 74).
4. `cancel-reservation-dialog.tsx` lines 58-60: fall back to `detailQuery.data` for `scheduledDate / startTime / seatNumber` like `memberName` does (check `LessonBookingDetailDto` carries them; it does for the list DTO).

Re-verify: B-036, B-054 (force 422 via `route`, expect seats/rows refetched), B-050, B-053.
