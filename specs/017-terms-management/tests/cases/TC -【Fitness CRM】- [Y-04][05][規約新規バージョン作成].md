- **Not used**: any implementation code under `src/app/**`, routes, schemas or seeds. The running app and the real API's behaviour are not the oracle; facts from an earlier live run (accounts, upload limits) are recorded as context only.
- **Missing inputs**: none.

## Test data reference and limitations

- `{RUN}` = the run date `YYYYMMDD`; `today` / `tomorrow` are the server's JST dates. Titles start with `ZZQA_`. The backend is shared, never reset, and rows cannot be deleted for real.
- **A new version rewrites its source's effectiveTo, so every source below is a record this run created (Unit 3 fixtures FX1…FX12).** Pre-existing rows may be opened in the form to look at the prefill and must be left via キャンセル — never saved.
- Sources (from Unit 3): FX1 `ZZQA_基本_{RUN}` JOYFIT 会員規約, start tomorrow · FX2 `ZZQA_全項目_{RUN}` FIT365 プライバシーポリシー, start tomorrow, end tomorrow+30, 表示順 5, switch ON, remarks · FX3 `ZZQA_共通_{RUN}` both brands 決済規約, start tomorrow · FX4 255-char full-width title 同伴規約 JOYFIT, 50-char version, 1000-char remarks · FX5 `ZZQA_公開_{RUN}` JOYFIT 退会規約, start today · FX6 `ZZQA_終了_{RUN}` JOYFIT 休会規約, start today-10, end yesterday · FX7 `ZZQA_終了日_{RUN}` JOYFIT 会員規約, start today-5, end today · FX8 `ZZQA_` + 250 `W` FIT365 プライバシーポリシー, start = end = tomorrow · FX10 duplicate of FX1, FX11 markup title, FX12 `ZZQA_二重_{RUN}` (residue fixtures, used only if they exist).
