## Source note

- **Used**: `specs/017-terms-management/spec.md` (User Story 3, FR-007/008/009/017/018, Edge Cases, Assumptions), `crm/requirements/Y-04.md` (FR-002, FR-003, permission matrix), prototype `.cache/fitness-crm-ui/src/pages/terms-form.tsx` (labels, messages, controls) and `terms-list.tsx` (the 新規登録 button), the two shared checklists, `src/lib/auth/demo-users.ts` (credentials only), and — for **field limits and error codes only** — the API contract (`contracts/terms-mutations.md`, `CreateTermsDto` and the POST responses in `src/lib/openapi.real.json`), which the checklist's limit-precedence rule names as a real limit source.
- **Not used**: any implementation code under `src/app/**`. The running app and the real API's behaviour are not the oracle.
- **Missing inputs**: none.
- **Integration round / backend**: fully on the real API (API-076 §3–§8). There is **no `integration-plan.md`**; the integrator's `api-integration-output/terms/report.md` was read as the gap register. **Target backend**: the value of `NEXT_PUBLIC_REAL_API_URL` in `.env` (confirmed by the user on 2026-10-19 as the correct target; currently `http://localhost:4000`).
