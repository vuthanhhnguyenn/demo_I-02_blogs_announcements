# TC -【Fitness CRM】- [Y-08-C][Exercise Form]

**Unit**: Y-08-C Form (per [../test-plan.md](../test-plan.md), unit 3 of 4 — executed **second**, after the Y-08-D create/edit part, per the plan's suggested order; it creates the exercises the Detail and List units read)
**Screen**: エクササイズ 登録／編集 (Exercise Create / Edit) — one form in two modes, routes `/exercises/create` and `/exercises/[id]/edit`. Each case states its mode through its pre-condition (PC-A = create, PC-B = edit).
**Scope**: both modes — every field and its validation; the three tabs; the English name and English steps with save-time translation, 要再翻訳, 再翻訳 and its confirm dialog (FR-014); the 公開 switch with the incomplete-step warning; the 器具種別→なし（自重） release dialog; the 種別不一致 save confirm; the unsaved-changes dialog; images, video URL, equipment linking, related exercises, tags; role gating; real-API behaviour; long-value layout.
**Out of scope** (per the test plan): the list (only the 新規登録 entry and the return target), the detail page (only used to read back what a case saved), the one-click publish toggles on list/detail, delete flows (used only to set up a deleted record), the reference-master screen (only used to create own test masters), mobile-app visibility (B12), E-03 screens, below 1024px.

## Test data reference

All data the cases write is **created by the cases** with the run prefix `TC-EX-<yyMMddHHmm>-<n>` (masters: code `tcex<yyMMddHHmm><n>`). Pre-existing records (71 seeded exercises, seeded masters, E-03 equipment, others' data) are **never edited or deleted** — they are only read and used as options, related targets and equipment links **from our own exercises**.

| F-FULL           | TC-177                 | every field: 3 協働筋, 休憩時間 60, YouTube URL, 5 images, steps 0–4 JP+EN, 2 linked バーベル equipment, 3 related seeded exercises, 2 tags ON, 非公開          |

Read-only inputs: ≥3 seeded exercises (related targets), E-03 equipment of type バーベル (≥2) and one other type, the master lists (counts at plan time: 12 categories, 30 muscles, 10 tool types incl. なし（自重）, 6 types, 9 tags — **verify at execution**, never hard-code). Image files: JPG ≤5MB, PNG, 5.1MB JPG, PDF, TXT, WebP, GIF.

**Data limitations** (referenced in Notes):

- **L1 — B9.** No machine-generated EN can exist in Round 1, so every "unedited / auto-generated EN" state is unreachable → `Block (B9)`.
- **L2 — F-EN is consumed** by cases that save it (TC-059, TC-075, TC-077, TC-078); run the read-only FR-014 cases first, or re-create F-EN.
- **L3 — Equipment names cannot be lengthened.** E-03 equipment is read-only for this feature, so long-name layout in the equipment list and mismatch dialog uses the longest existing names (TC-216).
- **L4 — Shared backend.** Counts (list header, master counts) are relative to a fresh read; other testers write concurrently.
- **L5 — Request replay** (server-side validation, `E-EXM-005`, denied-role POST) needs DevTools "Edit and resend" or the execute-testcases API helper; if unavailable, record `Not run (tooling)`.
- **L6 — B8 on edit.** The edit form shows レベル empty, so every edit-save case must re-select レベル first (otherwise 「レベルを選択してください」 blocks the save — that is B8, not NG).
- **Cleanup**: unpublish then delete every `TC-EX-` exercise; delete own masters after the exercises that use them (test plan Data policy).
