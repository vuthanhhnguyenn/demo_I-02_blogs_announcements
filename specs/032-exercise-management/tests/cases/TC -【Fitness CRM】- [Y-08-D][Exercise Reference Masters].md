# TC -【Fitness CRM】- [Y-08-D][Exercise Reference Masters]

**Unit**: Y-08-D Reference Masters (per [../test-plan.md](../test-plan.md), unit 4 of 4)
**Screen**: 参照マスタ管理 (Reference master management) — route `/exercise-master`
**Scope**: the six tabs カテゴリ / 筋肉部位 / 器具種別 / エクササイズタイプ / タグ / 用語解説 — per tab: count badge, search + result banner, table, create dialog, edit dialog, delete confirm, in-use (参照中) delete block; the page header (title, 本部 badge, 「<tab>を登録」 button, back link); role gating; the downstream reflection of masters into the exercise form / list filters (read-only check there) and, for 器具種別, into E-03 (read-only check).
**Out of scope** (per the test plan): the exercise list / detail / form as screens of their own (Y-08-A/B/C — used here only to create the referencing test exercise and to read options); E-03 トレーニング機材管理 screens (only a read-only look at the 器具種別 options); Y-09; mobile-app use of masters; tag grouping by category (Delta 3 / B18, pending PO).

**Data limitations** (referenced in Notes):

- **L1 — 用語解説 true-empty** needs the tab to hold 0 rows at execution. Run TC-028 **before** TC-041. If someone else already created a glossary entry → `Not run (no data)`; never delete others' rows.
- **L2 — Shared counts.** Tab badges / header count move when others write. Compare against a fresh read (badge vs rendered rows vs API `totalItems`) in the same moment, never against the plan-time numbers.
- **L3 — >100 rows per tab** (beyond the option `limit: 100`) is not reachable without creating ~100 masters; TC-006 checks completeness only on the largest seeded tab (筋肉部位).
- **L4 — Tag references** cannot be produced while B15 stands (TC-108 → `Block (B15)`).
- **L5 — "Deleted master still displays on existing exercises"** is unreachable through the UI: an in-use master cannot be deleted (TC-105/TC-109) and there is no 有効/無効 toggle. TC-116 covers the option-removal half only.
- **L6 — Forced requests** (server-side validation, code-immutability, denied-role API calls) need DevTools request editing / replay or the `execute-testcases` API helper; without tooling → `Block (tooling)`.
- **L7 — 401 cases** need the session tokens cleared/expired via DevTools mid-session.
- **Cleanup**: delete `TC-EX-` exercises first (unpublish if needed), then every `tcex…` / `TCEX_…` master. Anything left behind is listed in the run report.
