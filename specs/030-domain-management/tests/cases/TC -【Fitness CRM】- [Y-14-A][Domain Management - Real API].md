# Test Cases: Domain Management (Y-14-A) — Phase 2 (real API)

> Driven by [test-plan.md](../test-plan.md), unit "Domain Management". Covers the single `/domains` screen: list, detail sheet, add/edit dialogs, delete dialog (no separate detail route exists). **New doc for Phase 2** — a sibling of [TC -【Fitness CRM】- [Y-14-A][Domain Management].md](TC%20-%E3%80%90Fitness%20CRM%E3%80%91-%20%5BY-14-A%5D%5BDomain%20Management%5D.md), which stays untouched as the Phase 1 mock-API record. This doc is written fresh against the real backend (`src/lib/api-real`, real Cognito), the refreshed spec/requirement doc (Y-14.md v2, GAP-60 update), and the refreshed prototype — it does not reuse or renumber the Phase 1 cases.

## ⚠️ Critical data-safety rule — read before executing

**Absolutely do not modify or delete any pre-existing domain.** The dev backend is real, shared, and has no seed reset — every domain already on the list when this run starts (seed data, real onboarded companies, other testers' fixtures, anything not created by this run) may be actively relied on elsewhere and **must be treated as read-only master data**:

- **Permitted on a pre-existing domain**: List/search/filter/pagination, and opening its **Detail Sheet** (read-only) — that's the only interaction surface this rule allows for data this run didn't create.
- **Forbidden on a pre-existing domain**: opening its **Edit dialog** or **Delete dialog** at all — even just to inspect and then Cancel. A misclick (Save instead of Cancel, Enter key, double-click) is exactly the risk this rule exists to remove, so the safe boundary is "never open the dialog," not "open it carefully."
- **Every case that edits, deletes, or auth-method-changes a domain must target only this run's own fixtures** (`QA Phase2 20260917 *` below). If a fixture needed for a case was already consumed/deleted by an earlier case, create a **fresh replacement** fixture under the same `qa-p2-20260917-0N.co.jp` prefix (next available suffix) rather than substituting a pre-existing domain.
- If a case's Test Data or Pre-condition would require touching a pre-existing domain to be executed as written, **stop and mark it `Block` — no fixture available** rather than improvising against real data. This applies even to cases that look "just view-only" if their pre-condition is an Edit/Delete dialog (PC-H/I/J/K below) — those preconditions are themselves fixture-only.

The preconditions and Test Data cells below have been written to comply with this — PC-H/I/J/K are fixture-only by definition, PC-L (Detail Sheet) may target any domain including pre-existing ones.
