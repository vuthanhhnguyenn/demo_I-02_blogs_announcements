## Scope

**In scope** — everything reachable from the single `/domains` screen, now backed by `src/lib/api-real`:

- Domain list: server-side search (`search`, matches 管理名+ドメイン, max 100 chars) + `authProvider` filter + paging (25/50/100), header count (`totalAllItems`) vs. filtered count
- Add-domain dialog (real `POST`, `E-DMN-001` duplicate handling, `E-VAL-001` field validation)
- Edit-domain dialog (real `PATCH`): 管理名 always editable; ドメイン/認証方式 disabled with a reason when the domain has ≥1 **active** linked staff (**D9**), auth-method-change confirmation dialog (now reachable, but only ever fires at 0 affected staff — see delta #2 below)
- Detail sheet: real `GET /{id}` (`createdByName`, falls back to raw uuid → 「—」), 紐づくスタッフ list via `emailDomain`-filtered staff query
- Delete dialog: server-enforced block (`E-DMN-004`), confirm-time re-check via `GET /{id}` (`staleTime: 0`)
- Role gating of the screen and its actions (System/Headquarter only)

**Out of scope** (navigation targets, unimplemented UI, or downstream systems — not tested here):

- **Staff Management (Y-01)** — a blocked deletion/edit directs the user there. Only the redirect/guidance message text is checked from this screen, not the Staff screen itself.
- **Login / auth routing (Y-13)** — the actual login-time effect of `E-DMN-006` (invite blocked, unregistered/inactive domain) and `E-DMN-007` (login blocked) belongs to Y-01/Y-13's own flows. Verified here only up to "the domain record's `domain`/`authProvider`/`isActive` fields persist correctly after save."
- **FR-015 / User Story 5 — status (isActive) column, enable/disable toggle.** See **delta #1** below: this is now a real, open scope conflict, not a settled Phase-2 deferral, but the built screen has **zero** status UI (confirmed: no `状態` column in `domain-table-columns.tsx`, no toggle action in row actions, no status field in `domain-detail-sheet.tsx`; `checklists/parity.md` PAR900–PAR902 are unticked "deferred"). There is nothing on screen to write a case against, so it stays out of scope for this round regardless of which spec version is treated as authoritative. **Flagged to the user, not silently dropped** — see the report at the end of this run.
- **Two-tab live cross-tab updates to `staffCount`** beyond what a single-user confirm-time re-check can exercise — see Coverage Focus for what _is_ in scope (the server-side re-check itself).

## Coverage Focus per Unit

Added to, not a replacement for, `gen-testcases`' full coverage walk (field-level validation, boundary values, role×scope matrix, empty/loading/error states, etc.). Phase 2 means BE-owned outcomes are now first-class, not deferred:

**Real-API / server-side behaviours**

- **Error codes end to end**: `E-DMN-001` (409, duplicate on register/edit) → inline field error; `E-DMN-002` (404, stale id) → generic toast, list refetches; `E-DMN-004` (409, delete blocked by active staff) → the confirm-time `GET /{id}` re-check backstop, dialog flips to blocked state rather than closing; `E-DMN-005` (409, domain/authProvider edit blocked by active staff) → inline blocked alert on the form, race backstop even though the UI pre-disables the fields; `E-VAL-001` (400) on empty/oversized fields; `E-AUTH-103` (403, non-HQ role) — should be unreachable via UI (menu/route already gates it) but confirm the direct-nav 403 path too.
- **401 session expiry**: trigger mid-session (expired/invalidated token) while on `/domains` and confirm the redirect-to-login / re-auth behavior common to the app, not a silent failure.
- **Server-side validation beyond the client's**: name max 100 chars, domain max 252 (Google SSO) / 126 (IDaaS) chars — spec FR-006a, Q&A Q6, superseding 253, search max 100 chars — confirm the server also rejects values the client-side Zod schema (`domain-form.schema.ts`) might not catch (e.g. a crafted request bypassing the client, if reachable via a second browser tab with stale JS) is out of black-box reach; focus on confirming the client's own max-length limits match the server's stated caps (no silent truncation/mismatch).
- **Real pagination**: page size 25/50/100 (200 was removed — `DOMAIN_PAGE_SIZE_OPTIONS` capped at 100 per the API's own limit clamp), header `totalAllItems` vs. filtered `totalItems` diverge correctly under an active filter, and `includeTotalAll` degrading gracefully (per integration-plan.md D11, falls back to the filtered count "under load").
- **Persistence after reload/re-login**: created/edited/deleted domains and status changes (to the extent status is even reachable — it isn't, see delta #1) survive a hard reload and a fresh login, since this is now a real persisted backend, not a mock DB that resets.
- **The `staffCount` active-vs-total question** — see delta #3 (resolved by Y-14 Bug No.14: `staffCount` total + `activeStaffCount`). This is the single highest-value new Phase 2 case: it tests a real, unverified server contract, not UI polish.

**Duplicate-domain detection** (carried over, still relevant against the real API)

- Case-insensitive match (`JoyFit.co.jp` vs `joyfit.co.jp`), match against domain string only (not 管理名), exclude-self-on-edit, edit-into-another's-domain collision (now a real 409 from the server, not a mock check).

**Domain-string / field format validation**

- Rejects `@` and other invalid characters; accepts bare domain only; name/domain/search at their real max-length boundaries (100 / 252 Google SSO · 126 IDaaS / 100), and a numeric TLD (`test.2`) rejected.

**Auth-method-change gating** — see delta #2. Test the real, accepted behavior (0-only), not the spec's original literal wording.

**Read-only creator/created-at fields** — present, not editable, not blank; see delta #5 for the three creator-display states.

**Role × scope gating** — System/Headquarter full access; Manager/Staff/Trainer/Observer zero access to both menu entry and direct `/domains` navigation (spec AS1.5, FR-014/FR-M系 権限マトリクス, SC-005) — all four non-HQ roles are `×` across every row, no self-only carve-out. Now also confirm the **real** 403 (`E-AUTH-103`) on a crafted direct API call is consistent with the UI gate, not just that the menu item is hidden.

**UI breakage under stress (at the 1024px floor)**

- Long/variable-length values in every place they render: max-length 管理名 (100 full-width Japanese chars) in the list column, detail sheet, delete-confirm title, and edit form; a 252-char unbroken domain-string token in the same four places; the longest 認証方式 badge label; a long `createdByName`; many staff rows in the 紐づくスタッフ list (scroll behavior); a long search query string near the 100-char cap.

## Suggested Order

1. **List/search/filter/empty-state/pagination** (P1, read-only, no side effects) — run first, establishes baseline against real data before anything is created.
2. **Register (create)** (P1) — creates the `QA Phase2` fixture domains later cases reuse. Includes duplicate-domain and format-validation sub-cases.
3. **Detail sheet** (P1/P2) — read-only, run against both seed domains and freshly-created fixtures (covers delta #5's three creator-display states).
4. **Edit** (P2) — 管理名-only edit (always allowed), then the domain/authProvider-locked-by-active-staff path and the delta #2/D9 confirm flow, on whichever fixture ends up with linked staff (may be `Block` per the data-policy note above if no staff fixture is available).
5. **Delete** (P2, destructive) — run after edit so edit's fixtures aren't prematurely removed; includes the clean-delete path and the server-enforced block path (`E-DMN-004`).
6. **Role-gating** (can run anytime, but last avoids burning HQ-authenticated setup work under non-HQ sessions) — Manager/Staff/Trainer/Observer, menu + direct-nav, plus the real `E-AUTH-103` check.
