## Guiding principle

**Spec first, UI kept.** E-01 260901_v4 is the contract. Where the real API cannot yet back a
spec'd UI element, the element **stays** (disabled with 「API未対応」 only when leaving it live would
silently lose operator input) and is stripped from request bodies at one seam, marked
`TODO(round2) Bn`. No spec'd control, column, badge or section is deleted to fit the API.

**Round 3 = not in the spec.** Prototype-only elements, and elements whose upstream decision is an
open TBD, are **commented out, never deleted**, under `// TODO(round3) R3nn: <reason>`. Nothing may
still reference them (imports, query params, form fields) so `tsc` / lint stay clean.

Mock API routes under `src/app/api/crm/lockers/**`, `src/app/api/_mock-db/**` locker tables and the
mock Zod schemas are **left untouched** (staffs / positions / stores / domains convention). They
simply stop being called by this feature.

**Two status fields, never mixed.**

| Field                          | Values → label                                                                          | Used on                                                                    |
| ------------------------------ | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Slot status `slotStatus`       | `available` 利用可 · `in_use` 使用中 · `pending_release` 開放待ち                       | slot grid, slot table, pending list, contract list 「スロット状態」 filter |
| Contract status `optionStatus` | `pending_start` 開始前 · `active` 利用中 · `pending_cancel` 解約予定 · `cancelled` 終了 | contract list status column / filter, contract detail badge                |

## Decisions

- **D1 No mapper layer.** Components use DTOs from `@/lib/api-real/types.gen` directly and rename in place (staffs / stores precedent).
- **D2 Form field naming.** `locker-form.schema.ts` and `locker-contract-form.schema.ts` switch to the real camelCase names (`locationCode`, `shapeType`, `orderType`, `slotStartNumber`, `lockMethod`, `openMethod`, `optionId`, `bottomOptionId`, `locationCaption`, `supplementaryNote`). Bounds come from the real schema (`locationCaption` ≤ 255, `pinCode` 4 digits, `reason` ≤ 500).
- **D3 Contract status labels.** `active` 利用中 · `pending_start` 開始前 · `pending_cancel` 解約予定 · `cancelled` 終了 (API-101 wording). Slot status keeps its own map. The 解約 button renders only for `active` and `pending_start` (API-101 §6.2 #2).
- **D4 Enum labels in one file.** `_constants/locker-enum-labels.constants.ts` holds `Record<Enum, string>` maps typed from the generated unions, so a new BE value fails `tsc`. Labels follow API-100 §7.5 (`dial_lock` ダイヤル錠, `key_lock` シリンダー錠, `padlock` 南京錠; `ic_lock` reserved, not selectable; four `orderType` values; `openMethod` 扉型 / 引き出し型). Prototype numbering labels that have no API value are dropped from the select.
- **D5 Display ids.** ロッカーID = `locationCode`; slot label = `${locationCode}-${slotCode}`; 会員ID = `memberNumber`. Route ids are UUIDs (`lockerId`, `optionContractId`); no `parseAsInteger` on ids.
- **D6 Counts.** Header badge / filter-banner baseline = `pagination.totalAllItems` via `includeTotalAll=true` on each list. Tab badges = `totalItems` of a `limit: 1` call per tab. `GET /crm/lockers/summary` is no longer called.
- **D7 Paging.** `API_PAGE_SIZE_OPTIONS` stays `[25, 50, 100]` (lists cap at 100). Slot list uses `limit: 200`. Bulk open is chunked to 50 ids per call.
- **D8 Sorting.** Only sort keys the API accepts are clickable. Others render as plain headers.
- **D9 Errors by code.** A local `_utils/locker-error.util.ts` maps `E-LOC-004/005/006/007/010/011/012/013/014/015/016/017` (E-LOC-015 shows the BE `userMessage`), `E-LOC-100/101`, `E-RATE-001` through `getApiErrorCode` / `resolveApiErrorMessage`. E-LOC-006 (stale `updatedAt`) triggers a refetch plus a 「他のユーザーが更新しました」 toast. All local `onError: toast.error` blocks are deleted (shared `MutationCache` toasts). Inline handling uses `meta: { suppressErrorToast: true }`.
- **D10 Optimistic lock.** Every PATCH / PUT / slot op sends `expectedUpdatedAt` or `expectedSlotUpdatedAt` from the last read.
- **D11 CSV.** Exports become server CSV downloads (raw `fetch` with auth → Blob → anchor). The four client-side CSV utils stop being imported. The cabinet-list CSV is Round 3 (R301).
- **D12 Location master.** The hard-coded `LOCKER_AREA_OPTIONS` A–S and the pending A/B/C/F enum are replaced by `GET /locker-locations`.
- **D13 Permissions.** Existing route guards stay. Assign and release use `canManageLockerContract`; observers keep view + pending export only (BE returns E-LOC-101 otherwise).
- **D14 Create flow.** `POST /lockers` creates all slots with the cabinet default lock. Rows of the per-slot lock table that differ are then sent as `PATCH /locker-slots/{slotId}` calls. A partial failure leaves the cabinet created and lists the failed slots in one toast.
