## Scope

**In scope — Unit 1 (list)**: everything rendered on `/contracts` itself:

- Table: 10 data columns (ID=`planCode` / 主契約名 / 契約タイプ / ブランド / 店舗 / 料金(税込) / 同伴特典 / 親主契約 / 契約者数 / 状態) + ⋯ action column; header title 主契約管理 with the unfiltered-total badge `N件`; 新規登録 button (entry point only).
- Toolbar: plan-name search (`契約名で検索...`, debounced, server-side `nameQuery`); 詳細フィルター panel (契約タイプ / ブランド / 店舗 searchable picker / ステータス / 同伴特典) with active-filter count badge; filtered-results banner `全 X 件中 Y 件を抽出中` + 条件をクリア.
- Server-side sort (ID / 主契約名 / 契約タイプ / 料金 / 状態), pagination + page-size selector, URL-state (search / filters / sort / page / limit).
- Empty state (unfiltered-empty and filtered-empty), list-query error handling.
- Row ⋯ menu: 編集 / 複製 / 削除 with the `contracts/count` probe (loading state, edit-blocked, copy-blocked, delete-blocked tooltips).
- List delete dialog (`主契約を削除しますか？`) and its success/error paths (`DELETE /admin/plans/{planId}`, 409 `E-PLN-002` / `E-PLN-003`).
- Role gating of the page and every list control (System / Headquarter / Manager / Staff / Trainer / Observer).

**In scope — Unit 2 (create route)**: `/contracts/create` in its three modes — 新規登録, 複製 (`?copyFrom=<id>`), 子主契約作成 (`?copyFrom=<id>&asChild=1`):

- Frame: page title per mode, back link `主契約管理に戻る`, the warning / copy banner, the 3-step stepper (基本情報 → 料金・条件 → 確認), キャンセル / 前のステップ / 次のステップ / 登録する, the form-level error banner, the discard dialog `変更を破棄しますか？`.
- Step 1 cards 基本情報 / ブランド・属性 / 説明 / 会員公開設定, incl. the 店舗 / 企業 / 親主契約 / 規約 pickers (real `GET /admin/stores`, `/admin/corporates`, `/admin/plans`, `/admin/terms`) and サムネイル画像 upload (`POST /media/presign` + `POST /admin/plans/{id}/images`).
- Step 2 cards 料金 (incl. the brand's 入会時費用 pair and `ブランド費用設定を見る →`) / 利用条件 (利用開始日, 回数上限, 8-row 利用可能時間) / 休会・退会 / 対象制限 / 複製設定 (複製・子主契約作成 only) / ステータス.
- Step 3 summary, the save (`POST /admin/plans` or `POST /admin/plans/{planId}/copy`), success toast and return to 主契約管理.
- Role gating of the route (direct URL included).

**In scope — Unit 3 (edit route)**: `/contracts/[id]/edit` — prefill from `GET /admin/plans/{planId}`, the edit-only locks (主契約ID, ブランド, 親主契約名 `登録後は変更できません`), the holder block on direct URL (US5 AS3), `PATCH /admin/plans/{planId}` incl. clearing nullable fields, 409 `E-PLN-001`, `変更を保存する`, return to the detail (`主契約詳細に戻る`) and cache invalidation, discard dialog, role gating.

**In scope — Unit 4 (detail)**: `/contracts/[id]` — `GET /admin/plans/{planId}` + store label (`GET /admin/stores/{id}`) + parent code lookup (`GET /admin/plans/{parentPlanId}`):

- Header: back link `主契約管理に戻る`, title = plan name, status and 契約タイプ badges; actions 複製 / 子主契約を作成 / 編集 (holder-disabled with tooltip) and the ⋯ menu with 削除 (blocked tooltip with both counts, or the delete dialog). The action buttons are checked up to "the right form route opens" — the forms themselves are Units 2/3.
- Header delete dialog `主契約マスタを削除しますか？` / `「<name>」を削除します。この操作は取り消せません。`, toast `主契約マスタ「<name>」を削除しました`, return to 主契約管理, 409 `E-PLN-002` / `E-PLN-003`.
- Tab 基本情報: left cards 基本情報 (11 fields incl. 店舗 and コピー元主契約 link) / 説明 / 会員公開設定 (incl. サムネイル or 未設定); right column status card (作成 / 更新), 料金・利用状況 (料金（税込） / 休会時請求額 / 現在の契約者数), 契約マスタの関係 (親主契約 + `子主契約（N件）` links).
- Tab 料金・条件: cards 料金 (+ 入会時費用（ブランド費用・税込） block and `ブランド費用設定を見る →`) / 利用条件 (利用開始日, 回数上限, 8-row 利用可能時間 incl. 終日 / 休業) / 休会・退会 / 対象制限.
- Tab 変更履歴: `GET /admin/plans/{planId}/history` — one row per changed field (更新日時 / 変更者 / 変更フィールド / 変更前 → 変更後), ステータス and 新規作成 badges, 20 entries per page.
- Tab state in the URL (`?tab=`), not-found / load-error states, role gating of the page, the actions, and the 変更履歴 tab.

**Out of scope** (navigation targets or separate units — checked only up to "the right route opens"):

- **Forms reached from the detail header** (複製 / 子主契約を作成 / 編集) — Unit 4 checks the landing URL and title only; field behaviour is Units 2/3.
- **Y-07 ブランド管理 費用 tab** — the target of `ブランド費用設定を見る →`; only the landing is checked. Its fee values are read (never edited) as the expected defaults.
- **Y-04 規約文書管理 / corporate master / store master** — the pickers' data is read-only input; their screens are opened only to read which rows are eligible (e.g. which terms are 適用終了).
- **Y-02 販売設定, G-02/G-03, A-01 契約タブ** — out of scope per spec.md Overview.

**Split rationale**: one screen = one unit.

- The row menu and the list delete dialog exist only inside the list → clustered into Unit 1.
- 新規登録 / 複製 / 子主契約作成 are one route (`/contracts/create`) whose three steps are a single step flow, and the three modes differ only by query params and the prefill → one unit (Unit 2). All field-level validation, pickers, brand-dependent fields, usage hours, and the step 3 summary are covered **once**, here.
- 編集 is a separate route with its own API (`PATCH`), its own business-rule block (holders → no form), its own locks and return target → its own unit (Unit 3). It re-uses Unit 2's field coverage as a **smoke** (one pass per step) and concentrates on what only edit does: prefill fidelity, clearing values, the 409 guard, and the return to the detail.
- 詳細 is its own route with its own endpoints (detail, history, store lookup) → its own unit (Unit 4). Its three tabs, the header actions, and the header delete dialog exist only inside it → clustered there. The header delete shares the list's API but has its own wording, toast, and landing → tested in Unit 4, not re-used from Unit 1.

## Coverage Focus per Unit

Added to, not a replacement for, `gen-testcases`' full coverage walk.

### Unit 1 — Main Contract List

**Real-API behaviours**

- **Server-side search / filter / sort / paging**: every request parameter is reflected in results that come from the server (`nameQuery`, `contractType`, `brandEnum`, `storeId`, `isActive`, `hasCompanionBenefit`, `sort`/`order`, `page`/`limit`). Combine filters (AND semantics). Sort must be server-side — with enough rows, page 2 continues page 1's order rather than re-sorting one page.
- **Totals**: header badge `N件` = unfiltered total and **does not change** while filtering; banner `全 X 件中 Y 件` where X = header N and Y = footer 全 Y 件. Both update after a delete. (Relies on the B1 workaround.)
- **Soft-deleted rows never appear**: dev holds ≥11 soft-deleted `QA …` plans (`MC-0011`…`MC-0021`); none may show in the list, the count, or the 親主契約 column.
- **Error codes the screen can receive**: 409 `E-PLN-002` (delete with holders) and 409 `E-PLN-003` (delete with 子主契約) → Japanese backend message toasted, dialog closes / list unchanged, row still present; 404 on a stale id (deleted in another tab, then deleted again here) → toast, list refetches; 403 `E-AUTH-103` on a replayed DELETE/list call with a non-permitted role token.
- **Server-enforced guards, not UI-only** (SC-002/SC-003): replay `DELETE` on a guarded master → 409 (see Data policy for which target is allowed). Replay `DELETE` with a Staff token against a QA fixture → 403.
- **Real two-tab conflict**: tab A opens ⋯ on a 0-holder QA parent (削除 enabled), tab B creates a 子主契約 of it, tab A confirms delete → 409 `E-PLN-003` toast, row stays. Also: tab A deletes a fixture, tab B (stale list) opens ⋯ / deletes it → graceful 404 handling.
- **Probe**: exactly one `contracts/count` request per ⋯ open; interim `契約者数を確認中です`; probe failure (block the request) must leave 編集 / 削除 disabled, not enabled.
- **401 session expiry**: invalidate the session while on `/contracts` (sign out in another tab / clear tokens), then search / open ⋯ / confirm delete → redirected to login with reason and return path; after re-login the same URL (filters intact) is restored.
- **Persistence after reload / re-login**: a deleted fixture stays gone after hard reload and after re-login with another HQ-capable account (System).
- **URL state** (D3): reload keeps every control's value and the same result set; back/forward steps through filter changes; an invalid URL value (`?contract_type=foo`, `?page=999`, `?limit=7`) degrades to a sane state (no crash, no blank table).

**Computed values & rendering rules**

- 料金(税込) shown as stored, no second tax (D5); ¥ thousands separators; ¥0 row.
- 店舗 column only for 特殊契約 (store name with icon), `―` otherwise (D8).
- 親主契約 `└ name`, `―` when none; 同伴特典 `あり` badge vs `―`; 契約者数 `N名` with thousands separators, `0名` greyed; 状態 有効 / 無効 badge.
- All nine 契約タイプ labels (`通常会員 / 1Day Pass / 家族会員 / キッズ会員 / 学生会員 / 法人会員 / 福利厚生 / プリペイド会員 / 特殊契約`) and five brands in both the badge and the filter options — and no others (FR-002). Old labels `1Day会員` / `福祉会員` must not appear.
- Removed items must stay absent: no コード column/search target, no extra columns (旧コード / 利用開始日 / …), no `すべてクリア` in the filter panel, no 削除理由 input.

**Row menu / business-rule blocks**

- 編集 disabled + tooltip `契約者が存在するため編集できません。新規マスタを登録してください` when holders ≥1; enabled → `/contracts/[id]/edit` when 0.
- 複製 disabled + tooltip `このプランは複製できません` when `isCopyable` false (a 特殊契約); enabled on a 子主契約 (FR-M005 sibling copy); enabled → `/contracts/create?copyFrom=<id>`.
- 削除 disabled + tooltip (a real tooltip, not a native `title`) `契約者 N名・子主契約 M件が存在するため削除できません` for: holders only, children only (`0名・1件`), both. Enabled only at 0/0.
- Delete dialog: title, body with the name, キャンセル leaves data untouched, 削除する → toast `「<name>」を削除しました`, list refetches, user stays on the list with filters intact; double-click on 削除する sends one request; no reason field (FR-014).
- Row click opens `/contracts/[id]`; clicking inside the ⋯ cell does not.

**Role × scope gating** (G-01 権限マトリクス)

- System / Headquarter: full list + all actions.
- Manager / Staff: list, search, filter, sort, row click available; 新規登録, 編集, 複製, 削除 denied with an explanation (FR-019). Server side: a replayed DELETE with their token → 403.
- Trainer / Observer: page denied by the app-wide guard (menu entry absent + direct `/contracts` URL blocked); a replayed `GET /admin/plans` with their token → record the server response (expected 403 per matrix).

**Empty / edge states**

- Filtered-to-zero (e.g. 同伴特典 あり on dev today) → empty state, search box, filters, banner, 条件をクリア and pagination stay mounted and usable (FR-020 / SC-006). 条件をクリア resets search too.
- Search: partial match, full-width vs half-width, upper/lower case (`Family` vs `family`), leading/trailing spaces, `%` `_` `'` `\` characters (no wildcard leakage, no error), a very long query; debounce (typing fast sends one request).
- Filter button count badge reflects the number of non-default filters; search alone does not count as a filter but does show the banner.
- 店舗 picker: keyword search, infinite scroll, selected label survives reload (label fetched by id).

**UI breakage under stress — at the 1024px floor** (repeat the headline ones at ≥1440px)

- 主契約名 at the form's maximum length in full-width Japanese, and an equally long **unbroken ASCII token**, in: the name column, the 親主契約 column of its child fixture, the delete dialog body, the success toast, the banner summary (as a search query).
- The longest existing store name in the 店舗 column, the 店舗 picker trigger (`max-w`), and the banner summary.
- Longest badge labels together on one row (`プリペイド会員` + `JOYFIT YOGA`), 9-digit price (¥ with 税込 overflow above 9 digits), 4+ digit 契約者数.
- All five filters active at once: filter panel wrapping, the count badge, the banner summary line.
- Delete-blocked tooltip with large counts; the tooltips near the right edge (side="left") not clipped.
- Pagination footer (全 N 件 / ページ / 表示件数) fits without overlapping at 1024px; table scrolls horizontally inside the card rather than the page.
