# Test Cases: Main Contract Detail — 主契約 詳細 (G-01) — Phase 2 (real API)

> Driven by [test-plan.md](../test-plan.md), unit 4 "Main Contract Detail". Covers `/contracts/[id]`: the header (back link, title, badges, 複製 / 子主契約を作成 / 編集 / ⋯ 削除), the three tabs 基本情報 / 料金・条件 / 変更履歴 (incl. `?tab=`), the header delete dialog, not-found / error states, role gating, 401, and layout under stress. **Out of scope**: the forms the header opens (Units 2 / 3; only the landing URL and title are checked here), the list (Unit 1; only its row click and the delete's landing are used), the Y-07 brand 費用 tab (landing only), and the store / corporate / terms masters (read-only input).

## ⚠️ Data-safety rule — read before executing

The dev backend is real, **shared**, and has **no seed reset**.

- This unit **reads** Unit 2's fixtures (N-IDs, from `TC -【Fitness CRM】- [G-01-01][Main Contract Form].md`) and creates its own throw-aways (D-IDs), named `QA TC G01 <date> detail-<purpose>`.
- Delete only the D-fixtures listed below for deletion. **Never** press 削除する, and never save an edit, on a pre-existing master (S1, seed `MC-0001`…`MC-0010`, other testers' rows) or on an N-fixture (Unit 1 and Unit 2 still need them).
- On S1 (the holder-bearing seed master), only read, hover, and open 複製 / 子主契約を作成 / 編集 forms, then leave via `キャンセル` without typing. No DELETE or PATCH replay targets S1 in this unit.
- The history set-up edits go to **D1 only**.
- Token replays (TC-093, TC-103, TC-106) target D-fixtures or read-only GETs. A replayed DELETE that unexpectedly succeeds is NG; record it in the footer.
- **Ladyroom (`[Ladyroom]`, TC-135–TC-146)**: these cases read the Form doc's L-fixtures (`QA-E02-AREA-PLAN-…`, named per the 029 test plan §8). TC-141 / TC-142 edit **only** the QA area `QA-E02-AREA-N` and restore it at once; never rename, re-condition or delete a pre-existing area.
