# TC -【Fitness CRM】- [Y-03-A][FC企業一覧] (FC Company List)

**Scope**: Unit 1 of [../test-plan.md](../test-plan.md) — the **FC企業一覧 (FC Company List)** screen only, route `/franchise-companies`: search, the 区分 / ステータス filters, the filter-result banner, sortable columns, pagination, row navigation, the per-row action menu (編集 / 削除 / delete-blocked), the delete confirmation dialog, and both empty states.

**Out of scope here** (covered by other units, referenced only as navigation targets): the FC企業詳細 screen (units 2 and 3), the 登録・編集フォーム (unit 4), 店舗詳細 `/stores/[id]` (Y-02, out of scope for the whole feature).

**Conflicts / open questions flagged (do not silently resolve at execution time)**

1. **List column header says 法人名（表示名）but the mockup's seeded values are formal names.** `fc-company-list.tsx` seeds `name: "株式会社フィットネスパートナーズ"` for FC-002, while `fc-company-detail.tsx` holds `formalName: "株式会社フィットネスパートナーズ"` and `displayName: "フィットネスパートナーズ"` for the _same_ company. FR-001 requires the **display name**. TC-009 asserts the FR-001 intent (display name) and flags the mockup's internal inconsistency — if the app shows the formal name in this column that is an `NG` against FR-001, not a seed quirk.
2. **Pagination footer is always rendered**, even for a single page. The common GUI checklist's _Pagination Link_ row expects "pagination is not displayed when records < 1 page"; the mockup renders the summary, the page nav and the 表示件数 select unconditionally. TC-042 / TC-045 are written to the **mockup** (footer present, ends non-interactive), with the checklist divergence noted — do not log `NG` for the footer merely being visible on a single page.
3. **No URL binding for search / filter / sort / page is stated** in either the spec or the mockup. TC-080 / TC-081 are written as open questions, not as pass/fail assertions.
4. **Staff (FC企業管理者職位) scoping (FR-037) is not modelled in V0 at all** — the spec's own traceability matrix records it as "_Not modelled in V0_". Per the plan's execution notes: if the mock auth layer cannot express "Staff + FC-admin title + company affiliation", record `Block`; if the Staff user is scoped but sees **all** companies, that is a genuine `NG`.

## Test data reference

Dataset described by the spec's examples and seeded in the reviewed mockup (`INITIAL_COMPANIES` in `fc-company-list.tsx`) — 5 companies:

| #   | FC企業ID | 法人名（列に表示される値）       | 直営/FC区分 | 管轄店舗数 | ステータス |
| --- | -------- | -------------------------------- | ----------- | ---------- | ---------- |
| 1   | `FC-001` | 株式会社ウェルネスフロンティア   | 直営        | 42         | 有効       |
| 2   | `FC-002` | 株式会社フィットネスパートナーズ | FC          | 8          | 有効       |

| 5   | `FC-005` | 株式会社関西フィット             | FC          | 0          | 無効       |

Derived expectations used across the cases: 区分 `直営` → 1 row; 区分 `FC` → 4 rows; ステータス `有効` → 4 rows; ステータス `無効` → 1 row; 区分 `直営` × ステータス `無効` → **0 rows**; the only company with `管轄店舗数 = 0` is **FC-005** (the enabled-delete fixture).

**Data limitations**

- **Multi-page states are unreachable.** 5 rows against a default page size of 50 (smallest option 25) means page 2, ellipsis windowing, an enabled 次へ, page clamping and condition-retention-across-pages cannot be exercised. The affected cases (TC-046, TC-047, TC-048) are pre-marked `Block — insufficient seed data`; do **not** log them `NG`. To exercise them, seed ≥ 51 companies and fully restart the dev server (the mock-db is a `globalThis` singleton — editing seed files has no effect on a running server).
- **The true-empty state needs a zero-row dataset** (TC-036) — unreachable while any company is seeded.
- **Long-string and escaping cases (TC-064…TC-069) require creating a company first** via unit 4's form. If the form is not yet reachable, record `Block` with that reason.
- Exact counts assume the 5-row dataset above; if the running app seeds differently, verify the count arithmetic against the actual dataset rather than the literal numbers.
