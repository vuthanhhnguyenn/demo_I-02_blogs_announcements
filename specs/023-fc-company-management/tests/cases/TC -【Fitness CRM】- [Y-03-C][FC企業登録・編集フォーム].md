## Validation message ↔ label rule

Every validation message must:

- sit **directly under the field** it is about, and
- name that field using the **exact text of its label**, with the same full-width parentheses and slashes.

This matters most for fields whose names are close: 電話番号 vs 担当者電話番号, 法人名（正式名称） vs 法人名（表示名）, 代表者名 vs 担当者名.

The rule is asserted in:

- TC-123–TC-134, the dedicated cases;
- the boundary and format cases TC-024–TC-070;
- TC-131, for server errors, which must be mapped back to the screen label and never shown as an API key;
- TC-132, which checks that the footer message matches the kind of error.

A field name that is missing, shortened, or taken from a different field → `NG`.
