**Data limitations** (referenced from Notes):

- **L1 — Shared backend, no seed reset.** All counts (紐付き機器数, list tab count) are "verify at execution": read before, act, compare the difference.
- **L2 — Status-changing cases use a throw-away `QA-E02-DEL-<n>`**, never `QA-E02-CTRL-8` (other units read its status).
- **L3 — B3 makes 異常 / 廃棄 controller states unreachable live**; cases needing a controller in those states are Block (B3).
- **L4 — 平均対応間隔 over real day gaps** is unreachable in one run (all status changes are the same day → expected `0日` with ≥2 rows). A multi-day gap needs history that already exists; otherwise Block (data).
- **L5 — 3-digit summary counts** need ≥100 devices on one controller (only なし-type devices can exceed 8 ports). Create via API loop with prefix `QA-E02-BULK-` only if cleanup is possible, else Block (data).
- **L6 — 「履歴はありません」** needs a controller with zero history rows; if every controller carries a creation row, the empty state is unreachable → Block (data).
- **L7 — Role scopes**: Manager = S-003 (Round 2 live); record Staff / Observer store before their cases. Staff account may ship on 職位 `未割当` (0 flags): check `/crm/me`, assign a real 職位 and re-login; still failing → Block (account).
